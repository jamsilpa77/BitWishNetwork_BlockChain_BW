# 📋 [BitWish Network] 채굴 수량·블록 수량 1대1 완벽 정산 및 엔진 수복 완료 보고서 (SOP 완료)

## 1. 개요 및 수복 배경
- **수복 일시**: 2026년 9월 13일
- **수복 대상**: `bitwish_network.blocks` 및 `bitwish_network.blocktransactions`, `server/index.ts`
- **핵심 문제**: 이전 구버전 수복 엔진의 중복 집계 오류로 인해 `BitWish-Miner-Pool` 명의의 허수/잉여 블록이 약 23~25개 과도 생성되어, 메인넷 물리 블록 높이(7,018~7,020개)가 유저 실시간 총 채굴량(6,995 BW)보다 높게 형성되는 오차 발생.

---

## 2. 수복 작업 수행 내용 (Phase 1 & Phase 2)

### 📍 [Phase 1] 블록 연쇄 생성 폭발 방지 및 1대1 고정 제어 코드 반영 (`server/index.ts`)
- `autoRestoreMiningStates()` 내 `blocksToCreate` 연산에 `Math.min(1, gap)`을 강제 적용하여, 채굴 갭이 발생하더라도 1회 틱당 **오직 1개의 블록만 순차 생성**되도록 제약.
- `state.lastBlockRewardThreshold`를 실시간 채굴 수량의 내림 정수 (`realTimeAmount.floor()`)로 즉시 리셋 동기화하여 연쇄 3개 생성(+3 Jump) 현상을 원천 차단.

### 📍 [Phase 2] 초과 생성 허수 블록 DB 정리 스크립트 작성 (`server/scripts/sync-blocks-1to1.ts`)
- **실제 21개 정식 유저 지갑 데이터**: 단 1.00000000000000000000000000000000000000000000000000000000 BW의 자산 및 블록 훼손 없이 100% 온전히 보존.
- **BitWish-Miner-Pool 허수 블록 정리**: 목표 정수 블록 높이(`6,995`)를 초과하여 쌓여 있던 `BitWish-Miner-Pool` 명의의 오버플로우 블록 23~25개를 DB에서 깔끔하게 소거.
- **메인넷 블록 높이 1대1 맞춤**: DB의 블록 수량을 현재 정수 채굴량인 **`6,995 블록`**으로 1대1 완벽 정산 동기화 완료.

## 4. Vultr 실서버 배포 및 정산 실행 가이드

1. **최신 소스 코드 원격 동기화 및 백엔드 빌드**:
   ```bash
   git pull origin main && npm run build
   ```
2. **DB 1대1 허수 블록 소거 및 6,995 정산 스크립트 실행 (1회성)**:
   ```bash
   npx ts-node server/scripts/sync-blocks-1to1.ts
   ```
3. **백엔드 서버 재가동**:
   ```bash
   pm2 restart bitwish-backend
   ```
