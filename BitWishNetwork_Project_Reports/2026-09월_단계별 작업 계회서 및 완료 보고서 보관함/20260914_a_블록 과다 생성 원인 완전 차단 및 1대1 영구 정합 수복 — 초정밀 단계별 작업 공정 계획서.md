### ❌ 근본 원인 A: `MonthlySettlement` 이중 집계 구조 결함
- **위치**: [`server/index.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\index.ts) `autoHealMonthlySettlements()` + [`BlockMiningService.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\services\BlockMiningService.ts) `auditAndSyncGlobalBlocks()`
- **결함 내용**:
  - `MonthlySettlement.totalAmount`는 `MiningState.accumulatedReward`를 기반으로 비율 계산하여 만든 파생 수치입니다.
  - 그런데 총 발행량 집계 공식이 `MiningState + BonusRecord + MonthlySettlement`를 모두 더합니다.
  - 즉 **MiningState(원본) + MonthlySettlement(원본에서 파생된 복사본)** → 같은 채굴량이 두 번 합산됩니다.
  - **결과**: 목표 블록 수가 실제 채굴량의 거의 2배 수준으로 부풀려져 과잉 블록을 계속 생성합니다.

### ❌ 근본 원인 B: `autoHealBlockTransactions()` 내 `lastBlockRewardThreshold` 하향 교정 로직
- **위치**: [`server/index.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\index.ts) L203~237
- **결함 내용**:
  - 서버 재시작 시 유저의 실제 물리 블록 수와 `lastBlockRewardThreshold`를 비교하여 threshold를 낮춰버립니다.
  - threshold가 낮아지면 → 이미 이전에 생성한 블록 구간을 다시 "미생성" 구간으로 인식 → 30초 주기 워커가 또 블록을 생성합니다.
  - **서버를 재시작할 때마다 이 로직이 반복**되어 블록이 점차 누적 증가합니다.

### ❌ 근본 원인 C: 소급 정산 레코드 중복 누적
- **위치**: [`server/index.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\index.ts) `autoHealMonthlySettlements()`
- **결함 내용**:
  - 서버 재시작마다 6월~현재 직전월까지 소급 정산 레코드를 생성합니다.
  - 이 레코드들의 `totalAmount` 합계가 총 발행량 집계에 산입되어 목표 블록 수를 계속 부풀립니다.
  - **밤 사이 서버가 정상 운영되는 동안 30초 × ~1,000회 = 약 1,000개 이상 허수 블록 과생성** 발생한 것으로 추정됩니다.

### 📍 [1공정] 총 발행량 집계 공식 이중 산입 원천 차단 (코드 수정)
- **대상 소스 파일**: [`server/services/BlockMiningService.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\services\BlockMiningService.ts) `auditAndSyncGlobalBlocks()` (L146~170)
- **수행 내용**:
  - 현재 총 발행량 공식: `MiningState + BonusRecord + MonthlySettlement` ← **이중 산입 결함**

  - **핵심**: 현재 채굴 중인 유저의 `accumulatedReward`(MiningState)는 집계에 포함하되, 이미 정산 완료되어 `accumulatedReward`가 0으로 초기화된 유저의 과거분은 `MonthlySettlement`에서 가져오는 **상호배타적(Mutually Exclusive) 집계 구조**로 전환합니다.

- **가시성 (Visibility)**:
  - 총 발행량 집계값과 블록 목표 수치가 `7,034`로 정확히 계산되어 대시보드 수치와 일치하게 됩니다.

- **효율성 및 수정 전/후 효과**:

  | 구분 | 수정 전 | 수정 후 |
  |:---|:---|:---|
  | 총 발행량 집계 | MiningState + MonthlySettlement = **이중 산입으로 목표값 2배 부풀림** | MiningState(현재 채굴 중) 만으로 집계 → **실제 채굴량과 1:1 일치** |
  | 허수 블록 생성 | 부풀려진 목표값만큼 30초마다 계속 블록 과생성 | 정확한 목표값 → 부족 블록이 없으므로 과생성 완전 차단 |

## 🔍 1. 현재 상태 및 원인 상세 설명

### 1) `502 Bad Gateway` 서버 마비 및 대시보드 '0' 표기 현상
* **현상**: `pm2 restart bitwish-backend` 실행 후 약 20~30초 동안 웹사이트 접속 시 `502 Bad Gateway` 에러가 발생하고 대시보드 수치가 `0`으로 표시됨.
* **원인**: [`server/index.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\index.ts) 파일에서 웹 서버 포트 개방(`app.listen(5001)`) 구문이 3개의 무거운 DB 전수조사 수복 함수(`autoHealBlockTransactions`, `autoHealMonthlySettlements`, `autoRestoreMiningStates`)가 **모두 끝난 맨 마지막에 실행되도록 작성**되어 있어, 부팅 후 약 30초 동안 5001번 포트가 완전히 닫혀 마비 상태가 됨.

### 2) 서버 재시작 시 vCPU 111%~130% 과부화 현상
* **현상**: 서버 재시작 시 순간적으로 CPU 점유율이 100%를 초과하며 랙이 발생함.
* **원인**: 1 vCPU / 1GB RAM의 소형 Vultr VPS 사양에서 부팅 직후 3개의 무거운 DB 수복 루프가 포트를 열기도 전에 싱글 코어 CPU 자원을 연속으로 100% 사용함.

### 3) 허수 블록 과다 생성 (약 7,036 BW 발행량 대비 8,000+개 블록 초과)
* **현상**: 실시간 유저 채굴 발행량 정수(7,036 BW)보다 블록 수가 1,000개 이상 과다 생성됨.
* **원인**: [`server/index.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\index.ts) 내 `autoHealBlockTransactions()`의 임계값(threshold) 자동 하향 구버전 코드가 서버 재시작마다 발동하여 30초 워커가 이미 생성된 과거 블록을 미생성으로 오인하고 10개씩 연속 가짜 블록을 생성함.

### 4) `stats.ts` API 500 에러 발생
* **현상**: 프론트엔드가 대시보드 데이터를 불러오지 못하고 `0`으로 표기됨.
* **원인**: [`server/routes/stats.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\routes\stats.ts)가 매 요청마다 무겁게 `new MongoClient` 커넥션을 새로 개설하여 메모리가 고갈되거나, DB `BonusRecord` 집계 시 Null 변환 처리가 누락되어 500 에러를 반환함.

## 🛠️ 2. 단계별 개선 작업 공정 계획 (Step-by-Step)

### 📍 [1공정] 백엔드 부팅 순서 혁신 (0.1초 포트 즉시 개방 — 502 Bad Gateway 원천 소멸)

- **수행 내용**:

  2. 시간이 걸리는 무거운 DB 수복 루프(`autoHealBlockTransactions`, `autoHealMonthlySettlements`)는 비동기 백그라운드 프로세스로 전환하여 웹 서버 응답을 0.001초도 블로킹(차단)하지 않도록 구조 개선.

### 📍 [2공정] `stats.ts` 대시보드 API 최적화 및 500 에러 원천 차단
- **대상 소스 파일**: [`server/routes/stats.ts`](file:///c:\BitWishNetwork_BlockChainMainnet\BitWishNetwork_MiningSystem\server\routes\stats.ts)

  2. 모든 aggregation 연산 시 `$toDouble` 변환부에 `$ifNull: [field, "0"]` 안전 장치를 적용하여 DB에 Null 필드가 존재하더라도 500 에러 없이 정확한 수치를 100% 리턴.

### 📍 [3공정] 블록 과다 생성 방아쇠 비활성화 및 1:1 허수 블록 DB 정밀 소거

- **수행 내용**:
  1. `server/index.ts` 내 threshold 하향 조절 로직 영구 비활성화.
  2. `sync-blocks-1to1.ts` 집계 공식을 대시보드와 100% 동일하게 통일 (`liveBoost` 및 `bonusStorage` 필드 교정).
  3. `data.header.blockHeight` 이중 중첩 구조까지 조건에 추가하여 목표 정수(7,036) 초과 허수 껍데기 블록 100% 정밀 안전 소거.
  4. **유저 21개 지갑의 실제 BW 채굴 자산(약 7,036 BW)은 단 0.00000001 BW도 손실 없이 100% 온전히 보존.**
