## 1. 전수조사 총괄 개요

BitWish 네트워크의 관리자 시스템(`/bitwish/testadmin`)은 단순한 데이터 열람 도구가 아닌, 글로벌 채굴 네트워크의 생명선인 **채굴률 제어, 보너스 관리, 무인 정산 및 타임락 거버넌스, KYC 신원 승인, 가맹점 인프라 승인, 온체인 자산 마이그레이션 스위치**를 총괄하는 최고 권한 컨트롤 타워입니다.

본 전수조사는 관리자 시스템의 9대 핵심 영역 전체를 코드 1줄 단위로 추적하여, 각 기능이 실제 마이닝 시스템(`MiningState`, `BonusRecord`, `MonthlySettlement`, `User`, `BitWishBlockchain`)과 어떻게 맞물려 있는지, 혹은 어떤 부분이 미구현·단절·왜곡되어 있는지를 낱낱이 파헤쳤습니다.

### 3.1 🚨 [심각한 결함] 반감기 정책 관리 (Halving) 완전 단절 분석
- **현행 코드 실태**:
  - `AdminPage.tsx` 1975~1980행:
    ```tsx
    {activeTab === 'halving' && (
        <div className="admin-panel">
            <h2>⏰ 반감기 정책 관리</h2>
            <p>반감기 스케줄 및 이력</p>
        </div>
    )}
    ```
  - `server/routes/admin.ts` 내에 반감기 관련 라우트가 단 1개도 등록되어 있지 않음.
  - 마이닝 엔진 `MiningController.ts`의 기본 채굴률은 여전히 `'0.25'`로 하드코딩되어 고정되어 있음.
- **영향 및 위험성**:
  - 백서 §1.4에 명시된 2028년 1월 선형 반감기($R_0 \times (1 - 0.05 \times m)$)가 관리자 화면에서 모니터링되거나 제어되지 않으며, 현재 상태로는 2028년이 도래해도 채굴량이 자동으로 줄어들지 않는 심각한 결함 상태임.

### 3.2 🌟 [정밀 맞물림 확인] KYC 관리와 월간 정산(MonthlySettlement) 간의 승격 브릿지
- **연동 메커니즘 (`server/routes/admin.ts` L610-621)**:
  ```typescript
  if (status === 'APPROVED') {
      const promotionResult = await MonthlySettlement.updateMany(
          {
              walletAddress: { $regex: new RegExp("^" + walletAddress + "$", "i") },
              migrationStatus: 'WAITING_KYC'
          },
          { $set: { migrationStatus: 'LOCKED' } }
      );
      console.log(`[Promotion] ${promotionResult.modifiedCount} records promoted to LOCKED for ${walletAddress}`);
  }
  ```
- **마이닝 시스템과의 상호작용 검증**:
  1. 관리자가 대시보드에서 유저의 신분증을 확인하고 [승인] 버튼을 클릭하면,
  2. `User.isKycVerified = true`로 변경됨과 동시에,
  3. 과거에 적립되었으나 KYC 미승인으로 묶여 있던 해당 유저의 모든 월별 정산 레코드(`MonthlySettlement`)가 즉시 `WAITING_KYC`에서 `LOCKED`로 자동 승격됩니다.
  4. 이에 따라 유저의 지갑 모달(`MyWalletModal.tsx`)에서 즉시 15일 타임락 D-Day 카운트다운 타이머가 작동을 시작합니다.
  - **평가**: 매우 정교하게 마이닝 정산 시스템과 맞물려 구동되고 있음을 확인하였습니다.

### 3.3 🌟 [정밀 맞물림 확인] 가맹점 승인(Partner)과 채굴 가속(+30%) 파이프라인
- **연동 메커니즘 (`server/routes/partner.ts` L382-419)**:
  1. 관리자가 가맹점을 승인하면 `MiningState.partnerStatus = 'REGISTERED'`로 변경.
  2. `MiningState.partnerBonusRate = '0.3'`이 부여됨.
  3. 백엔드가 즉시 채굴 속도를 재계산:
     $$\text{currentTotalRate} = \text{baseWithBonuses} + (\text{baseRate} \times 0.3)$$
  4. 가맹점 승인 축하금 3.0 BW가 `MiningState.accumulatedReward`에 즉시 가산되고 `approvalBonusPaid = true`로 마킹되어 중복 지급을 원천 방지함.
  - **평가**: 가맹점 심사 승인이 실시간 채굴 속도 및 잔고 증가로 즉시 직결되는 완벽한 상호작용 구조를 갖추고 있습니다.

### 3.5 🟡 [주의 결함] 마이닝 리셋 시 블록 생성 임계점(Threshold) 미초기화 위험
- **현행 코드 실태 (`server/routes/admin.ts` L73-84)**:
  - `MiningState` 리셋 시 `isMining: false`, `miningStartTime: null`, `accumulatedReward: "0"`으로만 갱신.
  - **누락된 필드**: `lastBlockRewardThreshold`를 '0'으로 함께 초기화해주지 않음.
- **영향**:
  - 기존에 10 BW까지 채굴하여 블록 임계점이 10으로 설정되어 있던 유저를 관리자가 0 BW로 리셋한 경우, 이 유저가 다시 채굴을 시작하여 1 BW, 2 BW... 에 도달해도 임계점(10)보다 작기 때문에 신규 1:1 블록 발행 트리거가 작동하지 않고 먹통이 되는 연쇄 결함이 발생할 수 있습니다.

## 4. 관리자 시스템 총괄 평가 및 필수 정합성 수복 과제

### 4.1 종합 평가
- **우수 분야 (KYC, 가맹점, 추천 보상, 전광판)**:
  - KYC 승인 시의 정산 레코드 일괄 승격 브릿지와 가맹점 승인 시의 +30% 채굴 가속 및 3BW 실시간 지급 로직은 매우 높은 완성도로 마이닝 엔진과 정합성을 유지하고 있습니다.
- **취약 분야 (반감기, 대시보드 통계, 리셋 무결성)**:
  - 반감기 관리 탭은 실제 기능이 전혀 구현되지 않은 빈 상태이며, 대시보드 4대 카드의 정적 하드코딩과 마이닝 리셋 시 블록 임계점 누락 문제는 즉각적인 수복이 반드시 필요합니다.

### 4.2 필수 정합성 수복 4대 과제

1. **[과제 1] 관리자 반감기 엔진 신설 및 연동**:
   - `GET /api/admin/halving/status`: 현재 반감기 단계, 현재 기본 채굴률, 2028년 1월 도래 D-Day, 예상 채굴률 시뮬레이션 API 구축.
   - `POST /api/admin/halving/apply`: 수동/자동 반감기 정책 반영 및 전 유저 `currentBaseRate` 일괄 동기화.
   - `AdminPage.tsx`의 빈 반감기 탭에 실시간 대시보드 및 제어 패널 완성.
2. **[과제 2] 대시보드 메인 지표 4종 실시간 DB 연동**:
   - `GET /api/admin/dashboard/stats` 엔드포인트 신설.
   - `User.countDocuments()`, `MiningState.countDocuments({ isMining: true })`, 전체 발행량 합산, `User.countDocuments({ 'kycApplication.status': 'PENDING' })`를 실제 데이터로 표출.
3. **[과제 3] 마이닝 데이터 리셋 시 블록 임계점 동반 리셋 수복**:
   - `lastBlockRewardThreshold = '0'`을 리셋 쿼리에 추가하여 리셋 후 채굴 재개 시 0->1 BW 블록 주조 연결고리가 끊어지지 않도록 무결성 확보.
4. **[과제 4] 어드민 계정 권한 DB 영구화**:
   - 메모리 상의 `subAdmins`를 MongoDB `AdminUser` 컬렉션과 연동하여 권한 부여의 지속성 보장.
