제공해주신 마스터 프롬프트와 비즈니스 요구사항을 단 한 글자도 빠뜨리지 않고 완벽하게 이행할 수 있도록, AI 개발 에이전트(Cursor,
Claude Code 등)가 실제 코드 작성을 지연 없이 수행할 수 있는 수준의 전체 프로젝트 폴더/파일 구조 지도와 단계별 초정밀 작업
계획서를 작성했습니다.

이 가이드는 단순 샘플링이 아닌, 멀티테넌트(Multi-Tenant) SaaS 및 화이트라벨 엔진의 기틀이 되는 실제 상용 아키텍처를 기준으로
설계되었습니다.

PART 2. 시스템 구축을 위한 단계별 초정밀 작업 계획서

프로젝트 기획부터 클라우드 상용 서비스 개시까지의 모든 여정을 6단계로 명확히 분할하여 작업 지침을 정리했습니다. 이 계획서는 AI 개발
에이전트가 "구현 순서"를 오판하지 않고 순차적으로 데이터 무결성을 유지하며 빌드하도록 돕습니다.

[Phase 1] 데이터베이스 기초 공사 및 멀티테넌트 코어 빌딩 (1~4주 차)

본 시스템은 테넌트 간의 물리적 장벽을 유지하면서 비용 효율을 달성해야 하므로, 데이터베이스 격리 아키텍처를 우선적으로 구축합니다.

1단계: 테넌트 식별 테이블 및 다이내믹 호스트 감지 아키텍처 구축

  - 테넌트 코어 스키마 설계 (tenants, tenant_domains, tenant_settings):
      - 각 테넌트의 고유 해시값(tenant_id), 기본 도메인, 연동된 커스텀 도메인, 화이트라벨 활성화 템플릿 종류(01~05),
        테마 컬러 정보, 로고 주소, PG 정보(MID, API Key) 테이블 생성.
  - NestJS 테넌트 식별 미들웨어 (TenantContextMiddleware) 개발:
      - 클라이언트로부터 유입된 요청 헤더의 Host 값을 판독하여 등록된 테넌트 정보가 유효한지 검색.
      - 유효한 요청일 경우 해당 요청의 Context에 tenant_id를 할당하여 모든 하위 Service 및 DB 계층에서 해당
        ID로 쿼리하도록 인터셉터 연결.

2단계: 핵심 50개 이상의 관계형 DB 엔티티 물리 설계

  - users, admins, roles, permissions를 통한 회원 및 세부 직군별 권한 관리(RBAC) 테이블 설정.
  - products, product_images, brands, categories를 계층형 데이터(Self-referencing
    Category) 구조로 설계하여 하위 카테고리 무제한 연동 지원.
  - purchase_requests (매입 요청), consignment_requests (위탁 요청),
    appraisal_certificates (감정 및 시리얼 데이터) 테이블 설계.
  - PostgreSQL 마이그레이션 도구 세팅 및 로컬 PostgreSQL Docker 컴포즈 컨테이너 구축.

[Phase 2] 테넌트 미들웨어 라우팅 및 RBAC 인증 시스템 개발 (5~8주 차)

SaaS 형태로 시스템을 배포하고 안전하게 권한을 통제하기 위해 Next.js의 도메인 매핑 가상 경로 기술과 NestJS의 가드(Guard)
기능을 구축합니다.

1단계: Next.js 15 App Router 테넌트 도메인 미들웨어 개발

  - Next.js의 middleware.ts를 활용하여 https://watch-exchange.com/products/1과 같은 주소로
    접근이 오면 내부적으로 https://platform.com/watch-exchange/products/1로 경로를 투명하게
    프록시 매핑(Rewrite) 처리.
  - 이를 통해 각 테넌트 고객사 사장님은 본인의 독자적인 도메인을 사용하여 마치 단독 쇼핑몰을 구축한 것과 동일한 사용자 경험을 확보.

2단계: 역할 기반 다중 사용자 인증 필터링 (RBAC & Multi-tenant JWT)

  - 관리자 등급(SUPER_ADMIN, TENANT_ADMIN, PRODUCT_MANAGER, ORDER_MANAGER,
    ACCOUNT_MANAGER)에 따라 API 진입을 제한하는 RolesGuard 개발.
  - 인증 가드는 검증된 관리자의 소속 tenant_id와 조회하려는 대상 리소스의 tenant_id 일치 여부를 대조하여 타 테넌트의 상품
    정보나 회원 정보를 열람하려는 공격(IDOR)을 방어.

[Phase 3] 정밀 감정, OCR 자동 추출 및 이미지 강력 보안 가공 (9~12주 차)

중고 명품몰의 자산 가치를 지탱하는 상품 등록, 감정, 보안 레이어 및 OCR 기술을 하나로 묶어 구축합니다.

1단계: 멀티미디어 업로드 및 실시간 실감형 보안 워터마킹 구현

  - Sharp 이미지 파이프라인 개발: 관리자가 상세 사진을 업로드(최대 10개, 개당 1MB 미만 제한 검증)하면 백엔드에서 강제 이미지
    압축, 리사이즈 및 엣지 가독성이 뛰어난 .webp 형식으로 변환.
  - 실시간 워터마크 합성: 변환 직전, 테넌트 설정값에 기록된 상호 텍스트(예: LUXURY MARKET) 또는 테넌트의 반투명 워터마크
    로고를 이미지 중앙과 사방 모서리에 자동 하드-인코딩 합성하여 AWS S3로 전송.
  - AWS CloudFront Signed URLs 연동: S3의 ACL을 Private으로 선언하고 상품 상세조회 페이지 렌더링 시점에
    백엔드에서 15분 만료 주기의 임시 서명 토큰 주소를 생성하여 리턴함으로써 크롤러의 무단 주소 수집과 소스 도용을 근본적으로
    제한.

2단계: 정밀 감정서 시스템 및 OCR 시리얼 자동 정합 모듈 연동

  - 관리자 페이지에서 감정서 이미지 업로드 시 AWS Rekognition API를 트리거하여 명품의 시리얼 넘버 영역 검출.
  - 추출된 가공 텍스트 정보와 정규표현식을 매핑하여 에르메스 각인 규칙, 샤넬 홀로그램 규칙에 맞는 형태인지 파악한 후 시리얼 넘버 인풋
    필드에 자동으로 바인딩 처리.
  - 상품 상태 등급(N, S, A, B, C)과 감정서 데이터 매핑 저장 프로세스 완료.

[Phase 4] 실시간 매입/위탁 전용 라이프사이클 및 상태 관리 머신 (13~16주 차)

비정상 상태 전이(결제도 하지 않은 위탁 상품의 강제 판매 전환 등)를 방지하기 위해 엄격한 상태 관리 엔진을 설계합니다.

1단계: C2B 매입 및 위탁 상태 엔진 구현

  - 매입 신청 파이프라인: 고객 신청 ➔ 임시 견적 ➔ 검수 입고 ➔ 정밀 감정 ➔ 최종 매입 확정 ➔ 대금 지급 ➔ 재고 원장 자동 전입
    ➔ 사이트 노출 대기.
  - 위탁 신청 파이프라인: 고객 신청 ➔ 실물 정밀 감정 및 감정서 발행 ➔ 위탁 상품 자동 등록 ➔ 위탁 판매 개시 ➔ 판매 완료 ➔ 위탁
    정산 대기 ➔ 고객 송금 완료.
  - 모든 상태 전환은 DB 트랜잭션 내에서 처리되며 오류 발생 시 이전 단계로 완벽히 롤백하는 구조 채택.

2단계: AI 상품 시맨틱 자연어 검색 엔진 구현

  - pgvector를 활성화하여 상품명, 브랜드 메타 정보, 상품 설명 텍스트를 고차원 공간의 벡터
    임베딩(text-embedding-3-small 활용) 데이터로 치환 후 저장.
  - 최종 소비자가 고객 화면에서 "검정색 클래식 가방" 등으로 검색하면 자연어 문맥을 추출하여 가장 의미적으로 유사도가 높은 실제 등록
    상품(예: "샤넬 클래식 플랩 백 캐비어 블랙 샴페인 골드") 순서대로 추천 및 렌더링.

[Phase 5] 테넌트 독립 동적 PG 연동 및 마진과세 실시간 세무 정산 (17~20주 차)

비즈니스 매출을 실제로 분배하고 각 테넌트가 정산 내역을 투명하게 확인하는 회계 회로를 생성합니다.

1단계: 테넌트 정보 기반 Dynamic PG 결제 엔진

  - 국내 4대 간편결제 및 PG(토스페이먼츠, 이니시스 등) API를 연동할 때, 고정된 환경변수를 보지 않고 세션에 포커싱된 테넌트의
    암호화된 PG Credential(상점아이디 MID, API Secret Key)을 DB에서 복호화해 런타임에 동적으로 주입
    및 세팅.
  - 이를 통해 플랫폼사(Super Admin)로 모든 금액이 유입되지 않고 각 테넌트가 설정한 그들의 직속 계약 PG 한도로 안전하게 매출
    정산이 직접 귀속됨.

2단계: 마진과세 실시간 회계 정산 엔진 구축

  - 중고 명품 사업 고유의 회계 지식(마진과세 방식) 반영.
      - 마진과세 부가세 산식: (실제 판매가 - 매입 원가) / 11 계산 처리.
      - 위탁 거래 정산 산식: 실제 판매가 - (실제 판매가 * 테넌트 수수료율) - PG 수수료 계산 처리.
  - 대표자용 통계 차트 대시보드 구현: 오늘의 총매출, 당월 예상 순이익, 브랜드 점유율 대비 재고자산 회전율 지표를 산출하여 화면에
    직관적인 시계열 차트로 시각화.

[Phase 6] 5대 데모 테넌트 생성 팩토리 및 최종 배포 (21~24주 차)

구현된 하나의 백엔드 인프라와 프론트엔드를 패키징하고, 단 1분 만에 임의의 5종 명품 데모 사이트를 배포할 수 있는 팩토리를 완성합니다.

1단계: 5대 가상 데모 템플릿 제네레이터 시스템 구현

  - Super Admin 영역에서 [데모 생성] 버튼 클릭 시, 5종 템플릿(종합몰, 시계전문, 가방전문, 의류전문, 경매) 각각에 맞추어
    카테고리와 기본 브랜드 메타 정보, 미리 설계된 30개 이상의 샘플 가상 상품 데이터가 PostgreSQL DB 테이블 내에 타겟
    테넌트 ID로 순식간에 복제 및 마이그레이션되는 자동 시드 제네레이터 스크립트 가동.
  - Next.js 템플릿 라우터에서 사용자가 사전에 정의된 Template Key에 맞는 화면 레이아웃과 CSS 프레임을 브라우저에
    마운트하여 최종 구매 의사가 있는 예비 창업주에게 각 템플릿 쇼룸을 실시간 제공.

2단계: Dockerize 및 AWS 인프라 구축, 통합 테스트 및 소스 보안 확인

  - 백엔드(NestJS), 프론트엔드(Next.js Client), 어드민 패널 각각을 경량화된 Alpine 기반 Node.js Docker
    이미지로 멀티 스테이지 빌드 최적화.
  - 프론트엔드 내에 마우스 클릭 이벤트 가로채기, 드래그 차단 스크립트, F12 개발자 도구 진입 감지 시 디버거 루프 생성(Debugger
    loop) 등을 통한 실시간 브라우저 소스 유출 방어책 적용.
  - GitHub Actions CI/CD 스크립트를 작성하여 메인 리포지토리에 푸시되는 시점에 AWS EC2 인프라 및 RDS
    PostgreSQL 인프라로 무중단 롤링 업데이트가 이루어지도록 통합 배포 환경 구축.

[Summary] 성공적인 개발을 위한 AI 에이전트 지시 행동 요령

AI 개발 에이전트(Cursor 등)에게 위 전체 내용을 그대로 하나의 마스터 프롬프트 컨텍스트 파일로 주입한 뒤, 개발을 지시하실 때는 다음과
같이 선언하시기 바랍니다.

"위 작업 계획서의 [Phase 1] 1단계: 테넌트 식별 테이블 및 다이내믹 호스트 감지 아키텍처 구축부터 작성해 줘. 한 번에 모든 단계를
만들려 하지 말고, 1단계에 해당하는 NestJS 데이터베이스 모듈의 tenant-db.connection.ts 코드부터 단계적으로
완성하면서 점검을 거칠 테니 단계별 진척도를 공유하며 작업해 다오."

이러한 고도의 정교한 아키텍처 설계 지도를 바탕으로, 직접 운영하는 명품 비즈니스의 성공과 향후 다른 소매 사장님들을 향한 대규모 솔루션
비즈니스 가치를 동시에 안전하게 획득하시기를 기대합니다.

수천만 원을 호가하는 실물 중고 명품 데이터가 도메인 테마에 맞추어 브라우저상에 에러 없이 안전하게 출력되는 상태가 확보되었습니다 [1].

    내역(04_sample_products_seed.sql) 기입 완료 [1].

  - 호스트 분석 미들웨어 (tenant-context.middleware.ts): 사용자가 유입된 브라우저 호스트 도메인을 실시간으로
    해석하여 적절한 tenant_id 꼬리표를 모든 하위 컨트롤러 및 서비스에 전달하는 장치 완성 [1].
  - 전역 DB 커넥터 및 배선함 (tenant-db.connection.ts, database.module.ts): pg 풀(Pool)
    방식을 채택하여 동시 20개 대기 배관을 관리하고, 테넌트 이탈 위협 시 내부 쿼리 단에서 보안 경고를 울리는 안전 수문장
    역할 구현 [1].
  - 통합 제어 및 부팅 관제탑 (app.module.ts, main.ts): 글로벌 프리픽스 api/v1 지정, 멀티테넌트 간 교차 출처를
    허용하는 동적 CORS 규칙 바인딩, 그리고 http://localhost:4000/docs 경로로 실시간 중계되는 최고급 API
    사양서(Swagger) 구동 성공 [1].
  - 빌드 오류 정합화: 빈 설정 파일로 인한 컴파일러 타겟 누락 오류(dist/main 모듈 미검출) 해결 및 4000번 좀비 프로세스
    충돌(EADDRINUSE) 강제 해제 기술 적용 [1].

③ 프론트엔드(Next.js 15 App Router) 동적 화이트라벨 뷰

  - 가상 경로 매핑 미들웨어 (middleware.ts): 사용자가 보는 브라우저 주소창 주소는 유지한 채, 내부 서버 소스코드는 동적 가상
    경로 /[tenant]/... 폴더로 은밀하게 매핑(Rewrite)해 주는 Next.js 전용 라우터 연동 [1].
  - 스타일 기틀 구축 (global.css): 테일윈드(Tailwind CSS) 컴파일 엔진 수용 및 동적 CSS 테마
    변수(--tenant-primary)를 위한 최상위 스타일 시트 생성 완료 [1].
  - 테넌트 공통 액자 레이아웃 ([tenant]/layout.tsx): Next.js 15 사양이 의무화하는 <html> 및 <body>
    최상위 노드 적용을 마치고, 테넌트 도메인명에 따라 로고 및 테마 헤더/푸터 컬러가 실시간 변환 탑재되는 아키텍처 조립 완료
    [1].
  - 메인 쇼룸 가변 페이지 ([tenant]/page.tsx): Unexpected eof 원인이 되었던 소스코드 가독 누락 문제를 전면
    해결하고, 에르메스 백 및 롤렉스 시계 카드가 등급 배지와 함께 출력되는 카드 갤러리 구현 완료 [1].
