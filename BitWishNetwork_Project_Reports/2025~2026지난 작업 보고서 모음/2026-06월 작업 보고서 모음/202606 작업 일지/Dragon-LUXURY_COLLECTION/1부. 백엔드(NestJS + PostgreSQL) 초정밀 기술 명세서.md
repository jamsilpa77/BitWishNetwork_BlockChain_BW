1부. 백엔드(NestJS + PostgreSQL) 초정밀 기술 명세서

(Backend Technical Specification Document)

본 명세서는 "용 컬렉션(YONG COLLECTION)" 멀티테넌트 SaaS 플랫폼 백엔드 시스템의 구조 설계, 데이터 보관 도면, 그리고 통신
제어 장치들의 아키텍처적 유기성을 정밀히 기록한 기술 문서입니다.

1. 아키텍처 설계 및 데이터 흐름 개요 (Architecture & Data Flow)

백엔드 시스템은 NestJS 10.x 프레임워크를 기반으로 하며, 구조적으로 느슨한 결합(Loose Coupling)과 의존성
주입(Dependency Injection) 패턴을 채택하고 있습니다.

[클라이언트 요청] 
       │
       ▼
 1. TenantContextMiddleware (헤더에서 x-tenant-id 식별)
       │
       ▼
 2. ProductsController (API 데스크 창구)
       │
       ▼
 3. ProductsService (비즈니스 로직 연산)
       │
       ▼
 4. TenantDbConnection (공용 Connection Pool 제어)
       │
       ▼
 5. PostgreSQL Database (실제 명품 데이터 적재실)

1.  클라이언트 요청 수신: CORS(Cross-Origin Resource Sharing) 수용 범위 내에서
    클라이언트(http://localhost:3000)의 비동기 HTTP 요청을 포트 4000번에서 수신합니다.
2.  미들웨어 단 식별: TenantContextMiddleware가 모든 요청의 공통 길목에서 헤더를 검사해 테넌트
    아이디(yong-collection)를 발라냅니다.
3.  컨트롤러 단: 라우터와 가드(Guard) 설정을 통과한 후, 서비스 객체로 데이터를 위임합니다.
4.  서비스 단: TenantDbConnection에서 전달하는 안전하게 분리된 격리 쿼리 엔진을 사용해 데이터베이스에 필요한 자원만
    호출합니다.
5.  데이터베이스 반환: PostgreSQL 엔진에서 연산된 Row 데이터가 역순으로 전달되어 최종 클라이언트에 JSON 명세 양식으로
    반환됩니다.

2. 데이터베이스 물리 DDL 및 인덱스 상세 설계 (Database Schema)

본 데이터 아키텍처는 다중 테넌트 환경에서의 완전 격리 및 데이터 무결성 보장을 최우선 목표로 합니다. 관계형 데이터베이스인
PostgreSQL 16.x를 기반으로 설계되었습니다.

2.1 물리 ERD DDL 구성

-- 1. 테넌트(고객사 매장) 테이블
CREATE TABLE tenants (
    id VARCHAR(50) PRIMARY KEY,                             -- 테넌트 고유 ID (예: 'yong-collection')
    name VARCHAR(100) NOT NULL,                             -- 테넌트 브랜드명 (예: '용 Collection')
    domain VARCHAR(100) UNIQUE NOT NULL,                    -- 접속 독립 도메인 주소 (예: 'localhost')
    logo_url VARCHAR(255),                                  -- 테넌트 대표 로고 이미지 주소
    theme_primary VARCHAR(20) DEFAULT '#D4AF37',            -- 테넌트 브랜드 시그니처 프라이머리 컬러 (골드)
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()       -- 생성 타임스탬프 (UTC)
);

-- 2. 브랜드 테이블
CREATE TABLE brands (
    id SERIAL PRIMARY KEY,                                  -- 자동 증가 고유 식별자 (PK)
    name VARCHAR(100) NOT NULL UNIQUE,                      -- 브랜드명 (예: 'HERMES', 'ROLEX')
    logo_url VARCHAR(255),                                  -- 브랜드 오피셜 로고 이미지 주소
    initial_letter CHAR(1) NOT NULL,                        -- 브랜드 알파벳 머리글자 (A-Z 이니셜 필터용)
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. 상품 테이블
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    tenant_id VARCHAR(50) REFERENCES tenants(id) ON DELETE CASCADE,  -- 외래키 (FK): 테넌트 삭제 시 상품도 동시 삭제
    brand_id INT REFERENCES brands(id) ON DELETE SET NULL,           -- 외래키 (FK): 브랜드 삭제 시 상품 정보는 보존하고 null 처리
    title VARCHAR(255) NOT NULL,                            -- 가방/시계 모델명
    price DECIMAL(12, 2) NOT NULL,                          -- 명품 실물 가격 (소수점 2자리 정밀도 포함)
    category VARCHAR(50) NOT NULL,                          -- 카테고리 (BAG, WATCH, CLOTHES 등)
    status_badge VARCHAR(20) DEFAULT 'USED',                 -- 상태 뱃지 ('USED' / 'NEW')
    main_image_url VARCHAR(255),                            -- 대표 썸네일 고해상도 이미지 주소
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

2.2 인덱스(Index) 고속 색인 설계

다중 입점 쇼핑몰 구조 특성상 상품 조회 시 수백만 건의 데이터가 누적되더라도 특정 매장(tenant_id)의 특정
카테고리(category)만 0.001초 만에 색인해 낼 수 있도록 **복합 인덱스(Composite Index)**를
장착합니다.

CREATE INDEX idx_products_tenant_category ON products (tenant_id, category);
CREATE INDEX idx_brands_initial_letter ON brands (initial_letter);

3. 테넌트 호스트 분석 미들웨어 (TenantContextMiddleware)

  - 위치: backend/src/common/middlewares/tenant-context.middleware.ts
  - 구현 아키텍처: Express 엔진 위에서 가동되는 NestJS 미들웨어입니다.

import { Injectable, NestMiddleware } from '@nestjs/common';
import { Request, Response, NextFunction } from 'express';

@Injectable()
export class TenantContextMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    const host = req.headers.host || '';
    let tenantId = 'yong-collection'; // 로컬 테스트 기본 분기 처리

    // 실제 프로덕션 서버에서 커스텀 도메인 주소로 접근 시 자동 분류 가동
    if (host.includes('yong-collection')) {
      tenantId = 'yong-collection';
    }

    // 통신 패킷(HTTP Header) 헤더에 식별값 강제 장입
    req.headers['x-tenant-id'] = tenantId;
    next();
  }
}

4. 동적 데이터베이스 커넥션 풀 매니저 (TenantDbConnection)

  - 위치: backend/src/common/database/tenant-db.connection.ts
  - 구현 아키텍처: REQUEST(요청 스코프) 주입 모델을 채택하되, 불필요한 DB 커넥터 누수를 막고 안정적인 부하 분산을 구현하기 위해
    클래스 정적 변수(private static pool) 기반의 싱글톤 풀(Singleton Pool)을 장착했습니다.

import { Injectable, Scope, Inject } from '@nestjs/common';
import { REQUEST } from '@nestjs/core';
import { Pool } from 'pg';

@Injectable({ scope: Scope.REQUEST })
export class TenantDbConnection {
  private static pool: Pool;

  constructor(@Inject(REQUEST) private readonly request: any) {
    // 서버 자원을 아끼고 단 하나의 영구 커넥터 대기 배관을 전역 재사용합니다.
    if (!TenantDbConnection.pool) {
      TenantDbConnection.pool = new Pool({
        host: 'localhost',
        port: 5432,
        user: 'postgres',
        password: 'POSTGRES', // 마스터 비밀번호 동기화 완료
        database: 'postgres', // 29종 데이터 적재소 연결
        max: 20,              // 동시 연결선 최대 20개 자동 분배 제한
      });
    }
  }

  // HTTP 패킷에 꽂혀 들어온 매장 식별자 수신
  getTenantId(): string {
    const tenantId = this.request.headers['x-tenant-id'] || 'yong-collection';
    return tenantId as string;
  }

  // 진짜 금고 쿼리 원격 조작기
  async query(sqlText: string, params: any[] = []) {
    const client = await TenantDbConnection.pool.connect();
    try {
      return await client.query(sqlText, params);
    } finally {
      client.release(); // 조작 완료 시 즉각 기계에 커넥션 반납 처리
    }
  }
}

6. TS 컴파일러 및 CLI 런타임 수립 규격

NestJS는 강력한 메타 프로그래밍 및 의존성 조입을 사용하므로 아래 옵션이 완벽히 장착되어 구동됩니다.

  - experimentalDecorators: true: @Injectable(), @Controller() 등의 특수 장식 스티커를
    활성화합니다.
  - emitDecoratorMetadata: true: 스티커를 번역할 때 해당 클래스의 원본 메타데이터 타입을 유실하지 않게 고정해 주는
    필수 기능입니다.
  - nest-cli.json: 윈도우 환경에서 tsc 및 빌드 타겟 경로를 잃고 멍하니 굳어버리는 버그를 완전 방어하는 수동 빌드 옵션을
    보조합니다.
