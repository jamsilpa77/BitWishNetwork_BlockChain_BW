1.  파워쉘 시스템 폴더 기본 경로(System32) 이탈 오류 해결:
      - PowerShell 최초 구동 시 윈도우 시스템 내부 폴더(C:\WINDOWS\system32)에서 Expo 프로젝트를 무단
        생성하려던 오류를 즉시 감지하여 안전하게 Ctrl + C로 중단시키고, 프로젝트 루트
        경로(C:\delivery-blockchain-platform)로 정확하게 복귀시켜 윈도우 환경 오염을 완벽히
        방어했습니다.
2.  Expo CLI 폴더 충돌 에러 해결 (directory has files):
      - 미리 배치 파일로 설계해 두었던 비어 있는 src 폴더가 존재하여 Expo 설치가 중단되자, PowerShell 환경에서
        Remove-Item -Recurse -Force src 명령어로 충돌 폴더를 동적으로 지우고 재설치를 유도하여 정상 빌드를
        마쳤습니다.
3.  윈도우 환경 Metro 웹 컴파일 경로 충돌 우회 (MIME Type 404 Error Bypass):
      - 컴퓨터 브라우저(localhost:8081)로 구동 시 백슬래시(%5C) 경로 해석 오류로 인해 모바일용 아이콘 폰트
        라이브러리(Ionicons)가 웹팩 번들링에서 깨지며 검은 화면(Black Screen crash)이
        발생했습니다. 이를 웹과 모바일에서 100% 공용 가능한 '표준 이모지(📍, ⭐, 🍲, 🍗) 레이아웃
        아키텍처'로 전환 설계하여 크롬 브라우저 상에 정상 가동시켰습니다.
4.  VS Code 워크스페이스 상의 Active File 혼선 수정:
      - 고객용 앱(customer-app)과 사장님용 앱(partner-app)의 메인 파일명(index.tsx)이 동일하여 발생한 작업
        경로 혼선을 VS Code 사이드바 확장 구조 분석을 통해 정확히 짚어내고 제자리를 찾아 사장님 노드 대시보드 코드를 정상적으로

1단계: 데이터베이스(DB) 보완 설계 DDL (libs/database/schema.sql)

배민/쿠팡처럼 음식점 카테고리(치킨, 피자 등)와 마트/쇼핑 브랜드(CU, 홈플러스 등)를 분리하여 가로 휠에 배치하고, 정렬 기준(거리, 주문
수, 별점 등)을 연산하려면 **system_categories 테이블을 독립적으로 신설하여 매장 테이블과 정밀하게 연결(정규화)**해야
합니다.

🛠️ 반영 방법

C:\delivery-blockchain-platform\libs\database\schema.sql 파일을 메모장이나 VS Code로 열고,
**아래의 '카테고리 다중 그룹과 배달비 필터가 보완된 진짜 최종 통합본'으로 완전히 덮어쓰고 저장(Ctrl + S)**해 주세요.

-- 1. 사용자 역할 및 권한 테이블
CREATE TYPE user_role_enum AS ENUM ('CUSTOMER', 'PARTNER', 'RIDER', 'ADMIN');

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role user_role_enum NOT NULL,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 2. 노드 운영자로서의 사장님 프로필 테이블
CREATE TYPE kyc_status_enum AS ENUM ('PENDING', 'APPROVED', 'REJECTED');

CREATE TABLE partners (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    store_name VARCHAR(100) NOT NULL,
    business_number VARCHAR(50) UNIQUE NOT NULL,
    wallet_address VARCHAR(42),
    kyc_status kyc_status_enum DEFAULT 'PENDING',
    kyc_verified_at TIMESTAMP WITH TIME ZONE,
    node_contribution_score INT DEFAULT 0
);

-- 3. [★ 보완 및 신설] 관리자가 생성하는 시스템 대분류 카테고리 테이블
CREATE TYPE category_group_enum AS ENUM ('FOOD', 'RETAIL'); -- 음식 마켓 vs 쇼핑/마트 마켓 구분

CREATE TABLE system_categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(50) UNIQUE NOT NULL,             -- 카테고리명 (예: '치킨', '피자', 'CU', '홈플러스')
    group_type category_group_enum NOT NULL,      -- 대분류 그룹 지정
    icon_emoji VARCHAR(10) NOT NULL,              -- 화면에 표출될 시스템 표준 이모지 (예: '🍗', '🏪')
    sort_order INT DEFAULT 0,                     -- 가로 휠 노출 정렬 순서
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- 4. 가맹 매장 테이블 (★ 대분류 카테고리 관계 맺기 및 기본 배달비 필터 컬럼 보완)
CREATE TABLE stores (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    partner_id UUID REFERENCES partners(id) ON DELETE CASCADE,
    category_id UUID REFERENCES system_categories(id) ON DELETE SET NULL, -- ★ 시스템 카테고리와 외래키 연결
    name VARCHAR(100) NOT NULL,
    address TEXT NOT NULL,
    latitude NUMERIC(10, 8),                           -- 거리 정렬을 위한 매장 위도
    longitude NUMERIC(11, 8),                          -- 거리 정렬을 위한 매장 경도
    is_open BOOLEAN DEFAULT FALSE,
    minimum_order_amount INT DEFAULT 0,                -- 최소주문금액 필터용 (예: 5000, 10000, 15000)
    base_delivery_fee INT DEFAULT 2000,                -- 기본 배달비 필터용 (예: 0, 1000, 2000, 3000)
    delivery_time_alttul VARCHAR(50) DEFAULT '12~27분',
    delivery_time_hanjib VARCHAR(50) DEFAULT '10~20분',
    delivery_success_rate NUMERIC(5,2) DEFAULT 100.00,
    review_quality_score NUMERIC(3,2) DEFAULT 5.00,
    reorder_rate NUMERIC(5,2) DEFAULT 0.00,
    order_count_30days INT DEFAULT 0,                  -- '주문많은순' 정렬 가중치용 (최근 30일 완료 주문수)

💡 왜 두 번째 코드가 맞을까요? (핵심 이유)

첫 번째 코드는 주소지와 알림 센터만 단순히 덧붙인 **'임시 과도기 코드'**였습니다.

반면, 사장님께서 질문하신 두 번째 코드는 사장님이 대기업 배달 앱 캡처본을 바탕으로 말씀해 주신 **동적 카테고리(FOOD/RETAIL 가로

설계도'**입니다.

만약 첫 번째 코드로 남겨두시면 아래 기능들이 시스템적으로 불가능해집니다:

1.  가로 휠 카테고리 분리 불가능: 음식점(FOOD)과 편의점/쇼핑(RETAIL)을 분리하여 띄워주는 system_categories
    테이블이 존재하지 않습니다.
2.  거리 순 정렬 불가능: 매장의 위도/경도(latitude/longitude)를 저장하는 칸이 없어 가까운 매장을 계산할 수 없습니다.
3.  필터 조절 불가능: 매장의 기본 배달비(base_delivery_fee)를 저장하는 칸이 없어 배달비 필터를 걸 수 없습니다.
