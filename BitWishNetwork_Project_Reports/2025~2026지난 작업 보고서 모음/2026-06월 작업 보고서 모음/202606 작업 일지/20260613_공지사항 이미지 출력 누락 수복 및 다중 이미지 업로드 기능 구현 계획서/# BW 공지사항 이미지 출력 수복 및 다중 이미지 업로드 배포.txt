# BW 공지사항 이미지 출력 수복 및 다중 이미지 업로드 배포 완료 보고서

공지사항 및 커뮤니티 게시글 등록 시 이미지가 표시되지 않는 결함을 수복하고, 최대 10개의 다중 이미지(개당 2MB 이하)를 등록 및 렌더링할 수 있도록 고도화한 뒤, 로컬 테스트 검증 및 실서버 배포까지 완벽하게 완료하였습니다.

---

## 🛠️ 주요 작업 내역 및 수정 파일

### 1. 데이터베이스 스키마 및 백엔드 API 개편
* **Mongoose 모델**: [bwCommunityModels.ts](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/server/models/bwCommunityModels.ts)
  * 기존 단일 이미지 `image` 대신 다중 이미지 보관을 위한 `images: { type: [String], default: [] }` 배열 구조 적용 확인.
* **백엔드 API**: [bw_community_api.ts](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/server/routes/bw_community_api.ts)
  * 일반 게시글 등록(`POST /posts`), 수정(`PUT /posts/:id`), 공지사항 등록(`POST /admin/notices`), 수정(`PUT /admin/notices/:id`) 시 `images` 배열을 수용하도록 개조.
  * 게시글 상세 조회 및 목록 조회 응답 시 `images` 필드를 매핑 및 반환.
  * **서버 유효성 및 안전 검사 강화**:
    * 업로드 개수 검사: `images.length > 10` 일 경우 차단 에러 반환.
    * 용량 초과 검사: 개별 이미지 크기가 2MB(2,097,152 bytes)를 초과할 시 업로드 차단.
    * **[추가 구현] 스크린샷 이미지 안전성 형식 검증**: Base64 데이터 접두어 포맷 검사 (`/^data:image\/(png|jpeg|jpg|gif|webp);base64,/`)를 삽입하여 해킹 목적의 악성 스크립트가 포함된 위조 파일 업로드를 서버 측에서 완벽히 필터링 차단.

### 2. Nginx 인프라 파일 업로드 용량 제한 해제
* **설정 파일**: [nginx_default](file:///c:/BitWishNetwork_BlockChainMainnet/nginx_default) & [nginx_ssl_config](file:///c:/BitWishNetwork_BlockChainMainnet/nginx_ssl_config)
  * 기존 Nginx 기본값(1MB)으로 인한 `413 Payload Too Large` 통신 장애 문제를 수복하기 위해, `server` 블록 내에 `client_max_body_size 30M;` 설정을 추가했습니다.
* **배포 스크립트**: [deploy_backend.js](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/scripts/deploy_backend.js)
  * 배포 수행 시 원격 실서버 `/etc/nginx/sites-available/default`로 수정된 SSL Nginx 설정을 자동으로 복사(cp)하고 `systemctl reload nginx`를 수행하도록 자동화 파이프라인을 추가 연동하였습니다.

### 3. 관리자 UI 다중 파일 업로드 및 편의성 개선
* **관리자 페이지**: [AdminPage.tsx](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/src/components/AdminPage/AdminPage.tsx)
  * 공지사항 작성 및 수정 시 다중 이미지 상태 `noticeImagesBase64: string[]` 적용.
  * 파일 `<input>` 엘리먼트에 `multiple` 속성 주입.
  * **클라이언트 사전 검증**:
    * 파일 첨부 시 `file.size`가 2MB 초과 시 경고창 알림 후 자동 제외.
    * 기존 파일과 합쳐서 10개를 초과할 시 경고창 발생 및 첨부 제외.
  * **썸네일 그리드 구현**: 업로드된 이미지들을 미려한 그리드 썸네일로 렌더링하고, 우상단 `✕` 버튼으로 개별 즉시 삭제 가능한 인터랙션 설계.
  * 공지 수정 시 기존 등록된 이미지 배열 데이터를 폼으로 연동.

### 4. 커뮤니티 상세 뷰어 및 사용자 글쓰기 이미지 지원
* **커뮤니티 팝업**: [BWCommunityWindow.tsx](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/src/components/BWCommunityWindow/BWCommunityWindow.tsx)
  * `Post` 인터페이스에 `images: string[]` 추가.
  * 상세 보기(`currentView === 'detail'`) 영역 본문 하단에 `selectedPost.images` 배열을 순차 렌더링해 주는 `<img>` 레이아웃 추가 (상하 스크롤 그리드 형태).
  * 일반 사용자 글쓰기(`currentView === 'write'`) 및 수정 폼 또한 다중 이미지 업로드 및 개별 삭제를 지원하도록 UI 및 API 통신 코드 추가.
  * 목록 보기에서 대표 이미지(첫 번째 이미지)가 썸네일 박스에 미려하게 출력되도록 연동.
