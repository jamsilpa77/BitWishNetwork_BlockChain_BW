당신은 블록체인 통합 웹 애플리케이션 전문 풀스택 개발자로, JavaScript, React(또는 유사한 프론트엔드 프레임워크), Node.js, MongoDB 및 PoW 합의 메커니즘과 같은 블록체인 기술에 깊은 지식을 보유하고 있습니다. 주어진 상세한 문서를 바탕으로 BitWishNetwork 가상 BW 포인트 채굴 홈페이지 및 채굴 페이지를 개발해야 합니다. 제공된 문서의 모든 단어, 세부 사항, 요구 사항을 빠뜨리지 않고 정확히 구현해야 합니다. 모든 단어를 분석하여 구현이 정확하고, 간단하며, 유지보수가 편리하고, 모든 제약 조건을 준수해야 합니다.

---

### 프로젝트 개요
#BitWishNetwork 가상 BW 포인트 채굴 홈페이지 및 포인트 채굴기 마이닝 페이지 개발 프로젝트를 수행합니다.

50자리 부동소수점 정밀 계산 시스템을 갖춘 BW 가상 포인트 채굴 시스템을 개발하고, 현재 BitWishNetwork PoW 독자 개발 블록체인을 보유하고 있으며, 채굴 마이닝 페이지를 구축하여 연결하려는 점을 명심하며 폴더 파일 시스템 구조를 만들어야 합니다.

🎯 **출석 보너스 체계**

| 출석 상태 | 보너스율 | 설명 | 일일 보상 증가 |
|-----------|----------|------|----------------|

🎯 출석 보너스 시스템 특징:**
1. **단순화된 구조**: 연속 출석일수와 관계없이 출석 체크 시 일괄 5% 보너스
2. **시간 제한**: 마지막 출석일로부터 24시간 유예 기간 내에만 보너스 적용
3. **일일 체크**: 매일 출석 체크를 완료하면 5% 보너스 획득
4. **출석 체크 방법**: 
예1) 출석 가능 날짜: 정각 오전 9시 당일 달력 날짜는 활성화("파란색")
예2) 출석 체크 상실 날짜: 전날 1일 정각 오전 9시부터 다음 날 2일 오전 8시 59분 59초까지 달력 날짜는 활성화("파란색")로 유지 되지만 2일 정각 오전 9시가되면 1일 날짜는 즉시 비활성화("회색"처리되고 영원히 유지됨)처리된다.
예3) 출석 체크: 1일 정각 오전 9시 부터 ~ 2일 오전 8시 59분 59초전 까지 출석 체크를 했다면 1일 날짜는 비활성화("빨간색"처리되고 영원히 유지되며 보너스 5%가 즉시 적용되고 기본채굴률에 포함되어 실시간 총 채굴량에 누적 반영되고 2일 정각 오전 9시가되면 0%로 초기화 된다.)

⚠️ 중요**: 출석 보너스는 마이닝 시작 후에만 받을 수 있습니다.

🧮 **출석 보너스 계산 공식**

출석_보너스율 = 출석_체크_완료시_5% (0.05)
최종_채굴률 = 기본_채굴률 × (1 + 출석_보너스율)

📊 **구체적 계산 예시**

4. **일일 추가 수익**: 0.0125 × 24 = **0.3 BW/일**

3. **최종 채굴률**: 0.25 × (1 + 0.00) = **0.25 BW/시간**

👥 **추천인 보너스 (Referral Bonus)** 

**BitWishNetwork의 추천인 보너스는 커뮤니티 확장을 위한 가장 강력한 동기부여 시스템입니다:**
**50단위 초정밀 부동소수점 계산 시스템으로 구현되어야하며 표기는 소수점 8자리까지만 표시하면 된다.

**추천 보너스" 
1. 페이지에는 -가입자 목록-과 -지급 목록-이 있으며 -가입자 목록-에서는 가입자의 지갑주소:BWxxxx와 가입한 년, 월, 일, 시, 분, 초와 실시간 누적 보너스 채굴 수량이 적립되며 매달 말일 23:59:59초까지 채굴 수량이 매달 적립되어 표시해 준다.

2. 페이지에는 -지급 목록-은 본인이 KYC통과를 전제로하고 가입자가 KYC통과 후 가입자 목록에 저장된 누적 보너스는 즉시 추천자의 "실시간 누적 보상" 즉시 지급되며 -지급 목록-에 등록 표시되어 영구 저장된다.
 
🎁 **추천인 특별 혜택**
1. **즉시 보너스**: 추천인코드 발급자와 가입자(지갑 생성자)는 각 **1 BW 즉시 지급** (첫 지갑 생성 시)

2. **추천인 보너스율**: 발급자는 **2% 영구 적용** (가입자 발생 시 마다 추가 반영영), 가입자는 **가입 시 1회만 2% 영구 적용** (재적용 불가)

3. **영구 관계**: 추천인 관계는 한 번 설정되면 영구적으로 유지

4. **KYC 연동**: KYC 통과 시에만 보너스 지급으로 가짜 계정 방지(추 훗날 개발 구현)

5. **실시간 추적**: 추천인 수와 보너스율을 실시간으로 확인 가능

6. **추로인 보너스 보관함 시스템**: 추천코드로 가입자 발생 후 "마이닝 시작"중이여도 즉시 기본 보상률과 편입되어 추천 보너스 채굴량이 상승 되지만 상승분은 "추천인 보너스 보관함"에 분리되어 실시간 반영된다.

7. **추천 보너스 보관함**: 추천 보너스 1명당 2%영구 적용 되는 보너스는 "추천 보너스 보관" 에 마이닝 "기본 보상률" 0.25BW x 1명당 2% = ? BW를 "추천 보너스 보관함"에 지속 보관되며 추천인 명수가 늘어나면 추가로 지속 "추천 보너스 보관함"에 보관된다.

7-1. 또한 가입자가 추가로 지속 발생 시에도 기본 보상률에 적용되어 채굴 보너스가 상승되어 "시간당 기본 보상률"에 편입 되어 보상 수량이 늘어 나지면 지속적으로 "추천인 보너스 보관"에 누적 반영된다.

7-2. 이 반영된 목록을 제대로 확인할 수 있는 방법은 "마이닝 페이지"에 "추천 보너스"설정에 -가입 목록-이 있으며 가입 목록에 가입자별로 출력되며 년, 월, 일, 몇, 시, 분, 초,에 가입자 발생부터 각 가입자로인해 발생된 채굴수량이 따로 수치화 되어 목록에 출력되며 데이터로 저장된다. 

7-3. 이렇게 저장된 가입자들의 보관된 수량들은 가입자가 추 훗 날에 실제로 KYC신청 기간이 되어 가입자의 KYC신청 승인 통과 되어야 추천자의  가입자별 수량이 본인의 시작 했음을 개개인의 단독 저장소에 완벽하게 저장 되어야 한다.(저장소에 분리 저장 시스템 하이브리드 MongoDB 저장소 구현해야한다.)

8. **추천 보상 보관함**: 추천인이 추천코드로 가입하고 추천자와 추천인이 각 1BW를 보상으로 받게 된다. 
이렇게 받게되는 추천인 보상 1BW는 "추천 보상 보관함"에 각각 보관 되며 "추천 보너스"설정 -가입자 목록-이 있으며 가입 목록에 가입자별로 출력되며 년, 월, 일, 몇, 시, 분, 초,에 가입자 발생부터 각 가입자로인해 발생되는 채굴 수량 옆에 추천 보상 1BW 함께 저장 출력되고 개인 단독 저장소에 완벽하게 저장 되어야한다.(저장소에 분리 저장 시스템 하이브리드 MongoDB 저장소 구현해야한다.)

   - **메뉴1: "출석 보너스" 설정 페이지**
     - 출석 보너스 달력 날짜 체크형(Attendance Bonus) 구현
     - BitWishNetwork의 출석 보너스는 사용자의 꾸준한 참여를 보상하는 핵심 시스템
     - 50단위 초정밀 부동소수점 계산 시스템으로 구현되어야하며 표기는 소수점 8자리까지만 표시하면 된다.
     - 출석 보너스 체계 테이블 구현:
       | 출석 상태 | 보너스율 | 설명 | 일일 보상 증가 |
       |-----------|----------|------|----------------|
       | **출석 체크 완료** | **5% (0.05)** | 🎯 **일일 출석 보너스** | **0.2625 BW/시간** |
       | **출석 체크 미완료** | **0% (0.00)** | ❌ **출석 보너스 없음** | **0.25 BW/시간** |
     - 출석 보너스 시스템 특징 구현:
       1. **단순화된 구조**: 연속 출석일수와 관계없이 출석 체크 시 일괄 5% 보너스
       2. **시간 제한**: 마지막 출석일로부터 24시간 유예 기간 내에만 보너스 적용
       3. **일일 체크**: 매일 출석 체크를 완료하면 5% 보너스 획득
       4. **출석 체크 방법**:
         예1) 출석 가능 날짜: 정각 오전 9시 당일 달력 날짜는 활성화("파란색")
         예2) 출석 체크 상실 날짜: 전날 1일 정각 오전 9시부터 다음 날 2일 오전 8시 59분 59초까지 달력 날짜는 활성화("파란색")로 유지 되지만 2일 정각 오전 9시가되면 1일 날짜는 즉시 비활성화("회색"처리되고 영원히 유지됨)처리된다.
         예3) 출석 체크: 1일 정각 오전 9시 부터 ~ 2일 오전 8시 59분 59초전 까지 출석 체크를 했다면 1일 날짜는 비활성화("빨간색"처리되고 영원히 유지되며 보너스 5%가 즉시 적용되고 기본채굴률에 포함되어 실시간 총 채굴량에 누적 반영되고 2일 정각 오전 9시가되면 0%로 초기화 된다.)
     - ⚠️ 중요: 출석 보너스는 마이닝 시작 후에만 받을 수 있습니다.
     - 출석 보너스 계산 공식 구현:
       출석_보너스율 = 출석_체크_완료시_5% (0.05)
       최종_채굴률 = 기본_채굴률 × (1 + 출석_보너스율)
     - 구체적 계산 예시 구현:
       - 예시 1: 출석 체크 완료 사용자 -
         1. **기본 채굴률**: 0.25 BW/시간
         2. **출석 보너스**: 5% (0.05)
         3. **최종 채굴률**: 0.25 × (1 + 0.05) = **0.2625 BW/시간**
         4. **일일 추가 수익**: 0.0125 × 24 = **0.3 BW/일**
         5. **월간 추가 수익**: 0.3 × 30 = **9 BW/월**
       - 예시 2: 출석 체크 미완료 사용자 -
         1. **기본 채굴률**: 0.25 BW/시간
         2. **출석 보너스**: 0% (0.00)
         3. **최종 채굴률**: 0.25 × (1 + 0.00) = **0.25 BW/시간**
   - **메뉴2: "추천 보너스" 설정 페이지**
     - 👥 **추천인 보너스 (Referral Bonus)** 구현
     - BitWishNetwork의 추천인 보너스는 커뮤니티 확장을 위한 가장 강력한 동기부여 시스템
     - 50단위 초정밀 부동소수점 계산 시스템으로 구현되어야하며 표기는 소수점 8자리까지만 표시하면 된다.
     - **추천 보너스** 
       1. 페이지에는 -가입자 목록-과 -지급 목록-이 있으며 -가입자 목록-에서는 가입자의 지갑주소:BWxxxx와 가입한 년, 월, 일, 시, 분, 초와 실시간 누적 보너스 채굴 수량이 적립되며 매달 말일 23:59:59초까지 채굴 수량이 매달 적립되어 표시해 준다.
       2. 페이지에는 -지급 목록-은 본인이 KYC통과를 전제로하고 가입자가 KYC통과 후 가입자 목록에 저장된 누적 보너스는 즉시 추천자의 "실시간 누적 보상" 즉시 지급되며 -지급 목록-에 등록 표시되어 영구 저장된다.
     - 🎁 **추천인 특별 혜택** 구현
       1. **즉시 보너스**: 추천인코드 발급자와 가입자(지갑 생성자)는 각 **1 BW 즉시 지급** (첫 지갑 생성 시)
       2. **추천인 보너스율**: 발급자는 **2% 영구 적용** (가입자 발생 시 마다 추가 반영영), 가입자는 **가입 시 1회만 2% 영구 적용** (재적용 불가)
       3. **영구 관계**: 추천인 관계는 한 번 설정되면 영구적으로 유지
       4. **KYC 연동**: KYC 통과 시에만 보너스 지급으로 가짜 계정 방지(추 훗날 개발 구현)
       5. **실시간 추적**: 추천인 수와 보너스율을 실시간으로 확인 가능
       6. **추로인 보너스 보관함 시스템**: 추천코드로 가입자 발생 후 "마이닝 시작"중이여도 즉시 기본 보상률과 편입되어 추천 보너스 채굴량이 상승 되지만 상승분은 "추천인 보너스 보관함"에 분리되어 실시간 반영된다.
       7. **추천 보너스 보관함**: 추천 보너스 1명당 2%영구 적용 되는 보너스는 "추천 보너스 보관" 에 마이닝 "기본 보상률" 0.25BW x 1명당 2% = ? BW를 "추천 보너스 보관함"에 지속 보관되며 추천인 명수가 늘어나면 추가로 지속 "추천 보너스 보관함"에 보관된다.
         7-1. 또한 가입자가 추가로 지속 발생 시에도 기본 보상률에 적용되어 채굴 보너스가 상승되어 "시간당 기본 보상률"에 편입 되어 보상 수량이 늘어 나지면 지속적으로 "추천인 보너스 보관"에 누적 반영된다.
         7-2. 이 반영된 목록을 제대로 확인할 수 있는 방법은 "마이닝 페이지"에 "추천 보너스"설정에 -가입 목록-이 있으며 가입 목록에 가입자별로 출력되며 년, 월, 일, 몇, 시, 분, 초,에 가입자 발생부터 각 가입자로인해 발생된 채굴수량이 따로 수치화 되어 목록에 출력되며 데이터로 저장된다. 
         7-3. 이렇게 저장된 가입자들의 보관된 수량들은 가입자가 추 훗 날에 실제로 KYC신청 기간이 되어 가입자의 KYC신청 승인 통과 되어야 추천자의  가입자별 수량이 본인의 시작 했음을 개개인의 단독 저장소에 완벽하게 저장 되어야 한다.(저장소에 분리 저장 시스템 하이브리드 MongoDB 저장소 구현해야한다.)
       8. **추천 보상 보관함**: 추천인이 추천코드로 가입하고 추천자와 추천인이 각 1BW를 보상으로 받게 된다. 
         이렇게 받게되는 추천인 보상 1BW는 "추천 보상 보관함"에 각각 보관 되며 "추천 보너스"설정 -가입자 목록-이 있으며 가입 목록에 가입자별로 출력되며 년, 월, 일, 몇, 시, 분, 초,에 가입자 발생부터 각 가입자로인해 발생되는 채굴 수량 옆에 추천 보상 1BW 함께 저장 출력되고 개인 단독 저장소에 완벽하게 저장 되어야한다.(저장소에 분리 저장 시스템 하이브리드 MongoDB 저장소 구현해야한다.)
     - 🔒 **추천인 보너스 분리 시스템** 구현 (지갑 만들기와 KYC 시스템은 추 후 개발 구현함)

   - 수수료 자동 분배: 생태계 조성 자금 70%, 개발팀 운영 자금 30%
   - 투명성: 블록체인 상에서 실시간 조회 가능
   - 제네시스 블록 생성 및 실시간 생성 블록 수 표시

5. **데이터베이스**
   - MongoDB 하이브리드 저장소
   - 유저별 독립 DB, 1명부터 천만 명까지 확장 가능
   - 채굴 데이터, 지갑 주소, 발행량, 보너스 데이터(출석, 추천, 보관함, 가입자 목록, 지급 목록 등) 저장
   - 추천 보너스 관련: 가입자별 데이터(지갑주소, 가입 시간, 누적 보너스 채굴 수량) 분리 저장, KYC 연동 시 지급 처리, 하이브리드 MongoDB로 분리 저장 시스템 구현

6. **개발 우선순위**
   - 2-6까지(블록체인 관련 제외) 구현 후 마이닝 페이지 완성
   - 이후 2-7(실시간 생성 블록), 2-8(제네시스 블록), 2-9(지갑 생성 수) 순으로 구현
   - 보너스 시스템: 마이닝 페이지 완성 후 출석/추천/가맹/프로필 설정 페이지 순으로 구현

7. **추가 요구 사항**
   - 모든 텍스트는 4개국 언어(한국어, 영어, 일본어, 중국어) 및 동남아권 언어 지원
   - 홈페이지에서 "가상" 단어 사용 금지
   - UI는 고급스러운 디자인, 복잡하지 않게 구현
   - 보너스 시스템은 "마이닝 시작" 후에만 작동

### 문서 분석 및 포함 여부
제공된 문서들은 BitWishNetwork 가상 BW 포인트 채굴 홈페이지 및 마이닝 페이지의 상세한 요구 사항을 다루고 있으며, 다음과 같은 주요 섹션을 포함합니다:
1. **프로젝트 개요 및 토큰 이코노미**: 총 발행량, 분배 비율, 수수료 구조 등.
2. **유저 구현 절대 준수 사항**: 전역 변수/함수/모달 사용 금지, 50자리 부동소수점 계산, MongoDB 하이브리드 저장소, 언어 지원 등.
3. **홈페이지 UI 구조**: 네비게이션, 실시간 채굴 상태 창, 다크/나이트 모드, 언어 변경 등.
4. **마이닝 페이지 및 보너스 설정**: 출석 보너스, 추천 보너스, 가맹 보너스, 프로필 설정.
5. **출석 보너스 페이지**: 달력 체크형 시스템, 계산 공식, UI 요구 사항.
6. **추천 보너스 페이지**: 가입자/지급 목록, KYC 연동, 보너스 보관함 시스템.
7. **기술 스택 및 폴더 구조**: React, Node.js, MongoDB, 블록체인 통합, 파일 구조 제안.

그러나 문서에는 다음과 같은 세부 사항이 **명시적으로 포함되지 않음**:
- **API 엔드포인트의 구체적인 정의**: 엔드포인트 경로, 요청/응답 형식, HTTP 메서드 등이 상세히 정의되지 않음.
- **TypeScript 컴파일 설정**: `tsconfig.json`이나 TypeScript 관련 설정이 명시되지 않음.
- **컨트롤러 파일의 메서드 및 Return 문**: 컨트롤러 구조나 메서드 시그니처가 구체적으로 정의되지 않음.
- **서비스 클래스 메서드 시그니처**: 서비스 레이어의 메서드 정의나 세부 로직이 포함되지 않음.
- **의존성 패키지 목록**: 필요한 npm 패키지나 의존성 목록이 명시되지 않음.

문서에서 언급된 기술 스택(React, Node.js, Express, MongoDB)과 제약 조건을 바탕으로, 요청된 요소(API, TypeScript, 컨트롤러, 서비스 클래스, 의존성 패키지)를 어떻게 구현할 수 있는지 아래에서 설명하겠습니다. 이는 문서의 요구 사항을 충족하면서 누락된 부분을 합리적으로 채워넣는 방식으로 진행됩니다.

### 1. API
문서에서 API 관련 요구 사항은 명시적으로 정의되지 않았으나, 마이닝 페이지, 출석 보너스, 추천 보너스 등의 기능을 구현하기 위해 필요한 API 엔드포인트를 추론할 수 있습니다. 아래는 문서 기반으로 제안하는 API 구조입니다.

#### API 엔드포인트 예시
- **마이닝 관련**
  - `GET /api/mining/status`: 마이닝 상태 확인 (시간당 기본 보상률, 출석 보너스, 추천 보너스, 일일 최대 보상률 등)
    - **Response**: `{ status: { baseHourlyRate: number, attendanceBonus: number, referralBonus: number, dailyMaxRate: number, attendanceStatus: 'ON' | 'OFF', networkStatus: 'CONNECTED' | 'DISCONNECTED' } }`
  - `POST /api/mining/start`: 마이닝 시작
    - **Request**: `{ userId: string }`
    - **Response**: `{ success: boolean, message: string }`
- **출석 보너스**
  - `POST /api/bonus/attendance/check`: 출석 체크
    - **Request**: `{ userId: string, date: string }`
    - **Response**: `{ success: boolean, bonusRate: number, newHourlyRate: number }`
  - `GET /api/bonus/attendance/history`: 출석 기록 조회
    - **Response**: `{ history: Array<{ date: string, status: 'CHECKED' | 'MISSED' }> }`
- **추천 보너스**
  - `POST /api/bonus/referral/register`: 추천 코드로 가입
    - **Request**: `{ referrerId: string, newUserId: string }`
    - **Response**: `{ success: boolean, referralBonus: number, immediateBonus: number }`
  - `GET /api/bonus/referral/list`: 가입자 목록 조회
    - **Response**: `{ referrals: Array<{ walletAddress: string, joinDate: string, accumulatedBonus: number, immediateBonus: number }> }`
  - `GET /api/bonus/referral/payout`: 지급 목록 조회
    - **Response**: `{ payouts: Array<{ walletAddress: string, payoutDate: string, amount: number }> }`
- **블록체인 관련**
  - `GET /api/blockchain/blocks`: 생성된 블록 조회
    - **Response**: `{ blocks: Array<{ blockId: string, timestamp: string }> }`
  - `GET /api/blockchain/supply`: 발행량 및 잔여 발행량 조회
    - **Response**: `{ totalSupply: number, issuedSupply: number, remainingSupply: number, issuanceRate: number }`

#### API 구현 방식
- **Express.js**: Node.js 서버에서 API를 처리하기 위해 Express.js를 사용.
- **MongoDB**: 유저별 독립 DB를 위해 MongoDB 컬렉션을 분리하여 저장.
- **보안**: 자체 보안 검증(예: 입력 유효성 검사, 인증 토큰 사용)을 통해 데이터 무결성 보장.
- **부동소수점 계산**: 50자리 정밀 계산을 위해 `decimal.js` 또는 유사한 라이브러리 사용, UI에서는 소수점 8자리로 표시.

### 3. 컨트롤러 파일의 메서드 및 Return 문
문서에서 컨트롤러의 구체적인 메서드는 정의되지 않았으나, API 엔드포인트를 기반으로 컨트롤러 파일의 구조를 제안합니다.

#### 컨트롤러 파일 예시 (`server/api/bonus.ts`)
```typescript
import { Request, Response } from 'express';
import * as BonusService from '../services/bonusService';

// 출석 체크 컨트롤러
export const checkAttendance = async (req: Request, res: Response): Promise<void> => {
  try {
    const { userId, date } = req.body;
    // 자체 보안 검증
    if (!userId || !date) {
      res.status(400).json({ success: false, message: 'Invalid input' });
      return;
    }
    const result = await BonusService.checkAttendance(userId, date);
    res.status(200).json({
      success: true,
      bonusRate: result.bonusRate,
      newHourlyRate: result.newHourlyRate,
    });
  } catch (error) {
    res.status(500).json({ success: false, message: 'Server error' });
  }
};

// 추천인 가입 등록 컨트롤러
export const registerReferral = async (req: Request, res: Response): Promise<void> => {
  try {
    const { referrerId, newUserId } = req.body;
    if (!referrerId || !newUserId) {
      res.status(400).json({ success: false, message: 'Invalid input' });
      return;
    }
    const result = await BonusService.registerReferral(referrerId, newUserId);
    res.status(200).json({
      success: true,
      referralBonus: result.referralBonus,
      immediateBonus: result.immediateBonus,
    });
  } catch (error) {
    res.status(500).json({ success: false, message: 'Server error' });
  }
};

// 가입자 목록 조회 컨트롤러
export const getReferralList = async (req: Request, res: Response): Promise<void> => {
  try {
    const { userId } = req.query;
    if (!userId) {
      res.status(400).json({ success: false, message: 'User ID required' });
      return;
    }
    const referrals = await BonusService.getReferralList(userId as string);
    res.status(200).json({ referrals });
  } catch (error) {
    res.status(500).json({ success: false, message: 'Server error' });
  }
};
```

#### 컨트롤러 특징
- **비동기 처리**: `async/await`를 사용해 비동기 작업 처리.
- **Return 문**: 각 메서드는 `res.status().json()`을 통해 명확한 응답 반환.
- **에러 처리**: try-catch 블록으로 서버 에러 관리.
- **자체 보안 검증**: 입력값 검증 후 처리.

### 4. 서비스 클래스 메서드 시그니처
서비스 레이어는 비즈니스 로직을 처리하며, MongoDB와 블록체인 통합을 담당합니다. 문서에서 서비스 클래스 메서드는 정의되지 않았으나, 요구 사항을 바탕으로 시그니처를 제안합니다.

#### 서비스 클래스 예시 (`server/services/bonusService.ts`)
```typescript
import { Decimal } from 'decimal.js';
import { MongoClient } from 'mongodb';

interface AttendanceResult {
  bonusRate: number;
  newHourlyRate: number;
}

interface ReferralResult {
  referralBonus: number;
  immediateBonus: number;
}

export const checkAttendance = async (userId: string, date: string): Promise<AttendanceResult> => {
  // MongoDB에서 유저의 마이닝 상태 확인
  const client = await MongoClient.connect('mongodb://localhost:27017');
  const db = client.db(`user_${userId}`); // 유저별 독립 DB
  const user = await db.collection('mining').findOne({ userId });

  if (!user || !user.isMining) {
    throw new Error('Mining not started');
  }

  const baseHourlyRate = new Decimal(0.25);
  const bonusRate = new Decimal(0.05); // 5% 출석 보너스
  const newHourlyRate = baseHourlyRate.times(1 + bonusRate).toNumber();

  // 출석 기록 저장
  await db.collection('attendance').insertOne({
    userId,
    date,
    bonusRate: bonusRate.toNumber(),
    timestamp: new Date(),
  });

  await client.close();
  return { bonusRate: bonusRate.toNumber(), newHourlyRate };
};

export const registerReferral = async (referrerId: string, newUserId: string): Promise<ReferralResult> => {
  const client = await MongoClient.connect('mongodb://localhost:27017');
  const referrerDb = client.db(`user_${referrerId}`);
  const newUserDb = client.db(`user_${newUserId}`);

  const baseHourlyRate = new Decimal(0.25);
  const referralBonusRate = new Decimal(0.02); // 2% 추천 보너스
  const immediateBonus = new Decimal(1); // 1 BW 즉시 지급

  // 추천인 및 가입자 정보 저장
  await referrerDb.collection('referrals').insertOne({
    referredUserId: newUserId,
    joinDate: new Date().toISOString(),
    referralBonus: referralBonusRate.toNumber(),
    immediateBonus: immediateBonus.toNumber(),
  });

  await newUserDb.collection('referrals').insertOne({
    referrerId,
    joinDate: new Date().toISOString(),
    referralBonus: referralBonusRate.toNumber(),
    immediateBonus: immediateBonus.toNumber(),
  });

  await client.close();
  return { referralBonus: referralBonusRate.toNumber(), immediateBonus: immediateBonus.toNumber() };
};

export const getReferralList = async (userId: string): Promise<Referral[]> => {
  const client = await MongoClient.connect('mongodb://localhost:27017');
  const db = client.db(`user_${userId}`);
  const referrals = await db.collection('referrals').find({}).toArray();
  await client.close();

  return referrals.map((r) => ({
    walletAddress: r.referredUserId,
    joinDate: r.joinDate,
    accumulatedBonus: r.referralBonus,
    immediateBonus: r.immediateBonus,
  }));
};
```

#### 서비스 클래스 특징
- **MongoDB 하이브리드 저장소**: 유저별 독립 DB(`user_${userId}`)로 데이터 저장.
- **부동소수점 계산**: `Decimal.js`로 50자리 정밀 계산 구현.
- **KYC 연동 준비**: KYC 통과 여부 확인 로직은 추후 구현을 위해 주석 처리.
- **데이터 저장**: 추천인/가입자 데이터, 보너스/보상 보관함 분리 저장.

#### 의존성 패키지 설명
- **express**: Node.js 서버 구축.
- **mongodb**: MongoDB 하이브리드 저장소 연결.
- **decimal.js**: 50자리 부동소수점 정밀 계산.
- **react, react-dom**: 프론트엔드 UI 구현.
- **axios**: API 요청 처리.
- **i18next, react-i18next**: 다국어 지원(한국어, 영어, 일본어, 중국어, 동남아권 언어).
- **typescript, @types/***: TypeScript 컴파일 및 타입 정의.
- **ts-node, nodemon**: 개발 환경에서 TypeScript 실행 및 서버 자동 재시작.
