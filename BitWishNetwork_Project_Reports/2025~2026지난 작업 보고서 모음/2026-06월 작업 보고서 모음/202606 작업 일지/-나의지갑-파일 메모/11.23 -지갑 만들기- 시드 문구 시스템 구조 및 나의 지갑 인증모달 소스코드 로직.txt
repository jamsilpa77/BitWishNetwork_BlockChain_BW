1. 시스템 구조 및 로직 설명 (BIP-39 표준)
실제 P2P 거래가 가능한 안전한 지갑을 만들기 위해서는 BIP-39 (Bitcoin Improvement Proposal 39) 표준을 따라야 합니다.

핵심 원리:
1 엔트로피 생성 (무작위성): 브라우저의 암호화 API(window.crypto)를 사용하여 예측 불가능한 256비트(32바이트)의 난수를 생성합니다. 이것이 지갑의 '핵심 씨앗'이 됩니다.

2 체크섬 계산: 생성된 난수의 유효성을 검증하기 위해 해시(SHA-256)를 돌려 체크섬을 붙입니다.

3 단어 변환: 난수+체크섬 데이터를 11비트씩 잘라서, 미리 정의된 2048개의 영어 단어 목록(Wordlist)과 매칭합니다.

4 결과: 총 24개의 단어(시드 문구)가 생성됩니다.

- 보안 원칙:

- 클라이언트 생성: 모든 과정은 사용자의 브라우저 내부에서만 이루어져야 합니다. 서버로 시드 문구를 전송하면 해킹 위험이 있습니다.

지갑 UI 및 언어 구현 오류 분석 보고서

1. 개요
사용자가 제기한 "나의 지갑" UI의 심각한 품질 저하 및 언어 미구현 문제에 대한 정밀 분석 결과입니다. 현재 구현된 결과물(Image 1)과 사용자가 제공한 참조 디자인(Image 2) 간의 불일치 원인을 규명하고, 구체적인 수정 방안을 제시합니다.

2. 언어 구현 오류 (Translation Implementation Error)

2.1 현상
UI 상에 한글 대신 dashboard.title, dashboard.statusActive와 같은 영문 키값(Raw Key)이 그대로 노출되고 있습니다.

2.2 원인 분석
-LanguageManager 데이터 구조: LanguageManager.ts파일 내 번역 데이터는 wallet이라는 상위 키 아래에 dashboard 객체가 중첩되어 있습니다.

// LanguageManager.ts
wallet: {
  dashboard: {
    title: '나의 지갑',
    ...
  }
}

-잘못된 호출: MyWalletModal.tsx에서는 wallet. 접두사 없이 키를 호출하고 있습니다.

// MyWalletModal.tsx (현재)
getTranslation('dashboard.title') // 실패 -> 'dashboard.title' 반환

-결론: LanguageManager의 translate메서드는 루트부터 키를 탐색하므로, dashboard라는 루트 키를 찾지 못해 실패합니다.

2.3 해결 방안
모든 getTranslation호출 시 wallet. 접두사를 추가해야 합니다.

-dashboard.title -> wallet.dashboard.title
-dashboard.statusActive -> wallet.dashboard.statusActive

지갑 UI 피드백 분석 및 개선 제안 보고서
1. 개요
사용자께서 지적하신 "숫자 데이터 공간 부족(Overflow)" 문제와 "텍스트 줄바꿈 및 정렬(Alignment)" 문제에 대한 원인 분석 및 해결 방안입니다.

2. 문제점 분석

2.1 숫자 데이터 공간 부족 (Numeric Overflow)
-현상: 현재 balance-row는 좌측에 라벨, 우측에 값을 배치하는 flex-row (가로 배치) 구조입니다.
-문제: justify-content: space-between으로 양 끝에 배치되어 있어, 숫자가 커지거나(예: 10,000.00000000 BW) 라벨이 길어지면 서로 공간을 침범하거나 겹치게 됩니다. 사용자 말씀대로 "빡빡한" 구조입니다.
-위험: 100억 단위 이상의 큰 숫자가 들어올 경우 UI 밖으로 삐져나가거나 줄바꿈되어 레이아웃이 깨질 수 있습니다.

2.2 텍스트 줄바꿈 및 정렬 (Text Alignment)
-현상: "추천보너스 보상 보관함"이라는 긴 텍스트가 공간 부족으로 인해 "추천보너스 보상 보관" / "함" 처럼 애매하게 줄바꿈되고 있습니다.
-문제: 줄바꿈이 되더라도 중앙 정렬이 되지 않아 시각적으로 불안정해 보입니다.
-요구사항: "추천보너스 보상" / "보관함" 형태로 자연스럽게 줄바꿈되고, 하단 텍스트가 중앙 정렬되기를 원하십니다.

3. 개선 방안 (Solution)
3.1 레이아웃 구조 변경 (가로 → 세로 변경 고려)
숫자 데이터의 안전한 표시를 위해, 공간이 부족할 경우 라벨과 값을 분리하는 방식을 제안합니다.

-안 1: 수직 스택 (Vertical Stack) - 권장

-- 라벨을 상단에, 값을 하단(또는 우측 하단)에 넉넉하게 배치합니다.
-- 숫자가 아무리 길어져도 라벨과 겹치지 않습니다.
-- 예시:
[추천보너스 보상 보관함]
[          10,000.00000000 BW]

-안 2: 가로 배치 유지하되 여유 공간 확보

-- 폰트 크기를 상황에 따라 조절하거나, 모달의 너비를 더 넓게 사용합니다. (하지만 모바일 대응에 한계가 있음)

3.2 텍스트 정렬 및 줄바꿈 처리
-HTML 줄바꿈 태그 활용: LanguageManager에서 텍스트를 추천보너스 보상<br>보관함 형태로 정의하거나, CSS로 특정 너비에서 줄바꿈을 유도합니다.
-텍스트 정렬: 라벨 컨테이너에 text-align: center 또는 display: flex; flex-direction: column; align-items: center;를 적용하여 줄바꿈 시 중앙 정렬되도록 합니다.

4. 작업 계획 (Action Plan)

1. CSS 수정 (MyWalletModal.css):
-- .balance-row의 구조를 개선하여 긴 데이터에 대응하도록 flex-wrap: wrap 또는 flex-direction: column 속성을 조정합니다.
-- 숫자(balance-value) 영역에 충분한 min-width를 주거나 줄바꿈을 허용하지 않는 white-space: nowrap과 스크롤/말줄임 처리를 고려합니다(단, 금융 데이터는 다 보여주는 것이 좋으므로 줄바꿈 배치가 낫습니다).

2. 번역 데이터 수정 (LanguageManager.ts):
-- "추천보너스 보상 보관함" 텍스트의 가독성을 위해 적절한 위치에서 줄바꿈이 일어나도록 수정하거나, UI 컴포넌트에서 스타일로 제어합니다.

위 분석 내용을 바탕으로, **"여유롭고 안전한 데이터 표시"**가 가능한 UI로 즉시 수정하겠습니다.

지갑 UI 긴급 분석 및 복구 보고서
1. 상황 개요
사용자께서 제공해주신 **참조 이미지(Image 2)**와 현재 구현된 결과물(Image 1) 사이에 심각한 불일치와 렌더링 오류가 발생했습니다. 이에 대해 깊이 사과드리며, 원인 분석과 즉각적인 복구 계획을 보고드립니다.

2. 원인 분석 (Root Cause Analysis)
2.1 콘텐츠 누락 및 레이아웃 붕괴 (Critical)
현상: Image 1에서 카드 내부의 텍스트(타이틀, 라벨, 값)가 대부분 사라지고, 핀 아이콘만 비정상적인 위치에 표시됨.
원인: 
MyWalletModal.css
에서 .balance-row를 flex-direction: column으로 변경하면서, 부모 컨테이너의 높이 계산이나 자식 요소의 정렬(Alignment)이 꼬여 콘텐츠가 시각적으로 사라지거나(0 height) 겹쳐버린 것으로 추정됩니다. 특히 align-items: flex-start와 width: 100%가 적용되었으나, 내부 텍스트 요소들이 렌더링 공간을 확보하지 못했습니다.
데이터 검증: 
LanguageManager.ts
와 
MyWalletModal.tsx
를 확인한 결과, 데이터와 번역 키는 정상적으로 존재합니다. 즉, 데이터가 없는 것이 아니라 CSS 스타일 오류로 인해 보이지 않는 상태입니다.
2.2 디자인 불일치 (Design Mismatch)
Image 2 (목표):
헤더: 보라색 그라디언트, 우측 상단 상태/로그아웃/새로고침 버튼 정렬.
탭: 아이콘 + 텍스트 형태.
카드: 좌측(잔액), 우측(추천 보너스) 2열 배치. 각 행은 좌측 라벨 - 우측 값(색상 적용)으로 명확히 구분됨.
하단: 주소창과 복사 버튼이 박스 형태.
Image 1 (현재):
카드의 내용이 비어있고, 핀 아이콘만 덩그러니 있음.
탭 디자인이 텍스트 위주로 보임.
3. 복구 및 수정 계획 (Recovery Plan)
사용자의 분노를 충분히 이해하며, "쓰레기" 같은 현재 상태를 "완벽한 복제" 수준으로 즉시 수정하겠습니다.

3.1 CSS 전면 재수정 (Rollback & Fix)
레이아웃 복구: .balance-row의 flex-direction: column을 제거하고, Image 2처럼 좌측 라벨 - 우측 값의 row 배치를 기본으로 하되, 공간 부족 시에만 줄바꿈(flex-wrap: wrap)되도록 수정합니다.
텍스트 가시성 확보: 모든 텍스트 요소(card-title, balance-label, balance-value)의 색상과 display 속성을 강제로 지정하여 무조건 보이도록 합니다.
디테일 일치:
헤더: 그라디언트 및 버튼 스타일 정밀 조정.
카드: 배경색(보라색/파란색/분홍색 박스) 및 핀 아이콘 위치 수정.
폰트: 숫자 폰트(Roboto Mono)와 텍스트 폰트 크기/두께 재조정.
3.2 텍스트 정렬 및 오버플로우 처리
긴 숫자 처리: 숫자가 너무 길어질 경우, 폰트 크기를 줄이거나(clamp), 줄바꿈되더라도 레이아웃을 깨뜨리지 않도록 word-break: break-all을 적용하되, 기본적으로는 우측 정렬을 유지합니다.
텍스트 줄바꿈: "추천보너스 보상 보관함"과 같이 긴 라벨은 max-width를 설정하여 자연스럽게 줄바꿈되도록 하고, 수직 중앙 정렬(align-items: center)을 적용합니다.
4. 결론
