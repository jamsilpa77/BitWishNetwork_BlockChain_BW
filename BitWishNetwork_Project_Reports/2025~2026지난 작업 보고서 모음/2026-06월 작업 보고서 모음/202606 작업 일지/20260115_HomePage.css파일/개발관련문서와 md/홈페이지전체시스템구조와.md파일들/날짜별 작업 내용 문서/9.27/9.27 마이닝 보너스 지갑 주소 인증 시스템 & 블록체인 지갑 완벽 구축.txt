그럼 지갑 주소 인증으로 모든게 이뤄져야되 알겠어?
그러니 기존 홈페이지로 연결하고 그 안에서 유저/관리자 시스템이 연결되면 되는거야 이해 했어?

## **완벽한 이해 보고서** 📋

### **현재 문제점 분석** ❌

**1. 잘못된 구조:**
- 현재: 별도의 유저/관리자 마이닝 페이지
- 문제: 홈페이지가 아닌 단순한 노드 채굴 마이닝 페이지

**2. 접근 방식 오류:**
- 현재: 유저/관리자 선택 후 지갑 주소 입력
- 문제: 홈페이지 통합 없이 분리된 시스템

### **올바른 구조 이해** ✅

**1. 홈페이지 중심 구조:**
```
홈페이지 (메인)
├── 지갑 주소 인증 시스템
├── 관리자 전용 지갑 주소 등록
├── 유저 지갑 생성/추천코드 가입
└── 마이닝 & 보너스 버튼
    ├── 관리자 시스템 (인증된 지갑)
    └── 유저 시스템 (일반 지갑)
```

**2. 접근 흐름:**
```
홈페이지 접속
↓
지갑 주소 인증
↓
관리자 지갑주소 확인
├── 관리자 → 관리자 시스템
└── 유저 → 유저 시스템
```

**3. 핵심 요구사항:**
- ✅ **하나의 홈페이지**에서 모든 것 시작
- ✅ **지갑 주소 인증**으로 유저/관리자 구분
- ✅ **관리자 전용 지갑주소** 등록 시스템
- ✅ **유저 지갑 생성** 및 **추천코드 가입**
- ✅ **마이닝 & 보너스 버튼**에서 시스템 연결

### **구현 방향** 🚀

**1. 기존 홈페이지 통합:**
- 현재 `Node_HomePage`의 기존 홈페이지 구조 활용
- 지갑 주소 인증 시스템 추가
- 관리자/유저 구분 로직 구현

**2. 시스템 연결:**
- 홈페이지 → 지갑 인증 → 마이닝 시스템
- 관리자 전용 지갑주소 데이터베이스
- 유저 지갑 생성 및 추천코드 시스템

**3. UI/UX 개선:**
- 홈페이지에서 모든 기능 접근 가능
- 지갑 주소 입력 → 자동 시스템 분기
- 관리자/유저 구분 없는 통합 인터페이스

### **결론** ✅

**완벽히 이해했습니다!**

현재는 **노드 채굴 마이닝 페이지**이고, 필요한 것은 **홈페이지 중심의 통합 시스템**입니다.

**지갑 주소 인증**을 통해 **관리자/유저를 자동 구분**하고, **하나의 홈페이지**에서 모든 기능에 접근할 수 있는 구조로 구현해야 합니다.

**이제 기존 홈페이지를 중심으로 통합 시스템을 구현하시겠습니까?** 🚀

### **1-1: 현재 홈페이지 파일 구조 완전 분석** ✅

**현재 구조:**
- **App.tsx**: 유저/관리자 선택 후 마이닝 페이지로 이동하는 구조
- **HomePage.tsx**: 실제 홈페이지 (지갑 생성, 인증, 마이닝 & 보너스 버튼 포함)
- **main.tsx**: React Router로 App.tsx 렌더링

**문제점:**
- App.tsx가 홈페이지 역할을 하지 않고 단순 선택 페이지 역할
- HomePage.tsx가 실제 홈페이지이지만 App.tsx에서 사용되지 않음
- 지갑 인증 후 마이닝 시스템으로 직접 연결되지 않음

### **1-2: 기존 지갑 시스템 및 인증 로직 파악** ✅

**지갑 시스템:**
- **walletService.ts**: Stellar 지갑 관리 (현재 주석 처리됨)
- **HomePage.tsx**: 지갑 생성, 인증, 주소 검증 로직 포함
- **지갑 인증 흐름**: 지갑 주소 입력 → 2차 비밀번호 → 사용자 타입 구분

**인증 로직:**
- 지갑 주소 형식 검증 (Stellar 형식)
- 2차 비밀번호 검증 (8자 이상)
- 관리자/유저 구분 (하드코딩된 관리자 주소)

### **1-3: 현재 마이닝 시스템과의 연결점 확인** ✅

**연결점:**
- HomePage.tsx의 "마이닝 & 보너스" 버튼
- 지갑 인증 후 마이닝 모달 표시
- 관리자/유저 구분 후 각각의 시스템으로 분기

### **1-4: 관리자/유저 구분 로직 설계** ✅

**현재 구분 로직:**
```typescript
const getUserType = (walletAddress: string): 'USER' | 'ADMIN' => {
  const adminAddresses = [
    'GADMIN123456789012345678901234567890123456789012345678901234567890',
    'GADMIN987654321098765432109876543210987654321098765432109876543210'
  ];
  return adminAddresses.includes(walletAddress) ? 'ADMIN' : 'USER';
};
```

**문제점:**
- 하드코딩된 관리자 주소
- 데이터베이스 기반 관리자 주소 관리 없음
- 동적 관리자 주소 추가/제거 불가능
