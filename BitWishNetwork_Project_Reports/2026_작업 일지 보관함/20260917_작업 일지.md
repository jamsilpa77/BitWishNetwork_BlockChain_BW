이 코드가 배치되었음에도 블록이 계속 생성된 3가지 치명적 원인은 다음과 같습니다:

stateAgg 합산식의 불완전성 (순수 채굴량만 집계):

miningstates의 accumulatedReward는 오직 유저들의 순수 마이닝 누적 수량만 더합니다.
하지만 유저들의 추천 보너스 보관함(referralBonusStorage), 추천 보증금(referralRewardStorage), 과거 정산 데이터(MonthlySettlement) 등 백엔드 실시간 총 BW 발행량 연산 대상이 빠져 있어 stateAgg[0]?.total 수치가 실제 전체 발행 BW보다 낮게 계산되었습니다.
이로 인해 currentBlocks >= Math.floor(stateAgg[0]?.total) 조건이 실제 전체 BW 기준과 불일치하여 차단막이 뚫렸습니다.

public static async auditAndSyncUserBlocks(walletAddress: string): Promise<{ createdBlocks: number; currentThreshold: string }> {

        const miningDb = mongoose.connection.useDb('bitwish_mining');
        const stateColl = miningDb.collection('miningstates');
        const state = await stateColl.findOne({ walletAddress: new RegExp('^' + walletAddress + '$', 'i') });
        if (!state) return { createdBlocks: 0, currentThreshold: '0' };
        const accumulated = new Decimal(state.accumulatedReward || '0');
        const lastThreshold = new Decimal(state.lastBlockRewardThreshold || '0');
        const nextThreshold = lastThreshold.plus(1);
        if (accumulated.gte(nextThreshold)) {
            const blocksToCreate = accumulated.minus(lastThreshold).floor().toNumber();

                    { _id: state._id },
                    { $set: { lastBlockRewardThreshold: newThreshold } }

문제의 원본 코드:

이 코드가 시스템을 망치고 있던 4가지 근본적인 기술적 이유는 다음과 같습니다:

1. 유저 채굴 수량이 0 BW여도 "공짜 허수 블록"을 강제 생성함
userBlockCount === 0 조건은 **"이 유저 명의로 만들어진 블록이 아직 0개인가?"**를 검사합니다.
신규 유저가 처음 회원가입을 하고 [마이닝 시작] 버튼을 누르는 그 순간, 당연히 이 유저 지갑의 블록은 0개이므로 조건문이 무조건 참(True)이 됩니다.
그 결과, 유저가 채굴을 0.0000001 BW도 진행하지 않았음에도 불구하고 마이닝 버튼을 누르자마자 1개의 물리 블록을 공짜로 강제 찍어내는 치명적 결함이 발생했습니다.
2. "1 BW = 1 블록" 대원칙 100% 위반
BitWish Network의 대원칙은 **"유저들이 실제 채굴하여 전체 BW 발행량이 1 BW를 돌파할 때만 1개 블록이 생성된다"**입니다.
그러나 이 코드는 유저가 실제 채굴을 해서 1 BW를 모으기도 전에, 단순 버튼 클릭만으로 채굴량과 아무 상관없는 허수 블록을 만들어냈습니다.
3. 신규 유저가 들어올 때마다 블록 수가 억지로 폭증함
만약 신규 가입 유저 10명이 들어와서 [마이닝 시작] 버튼을 누르면, 채굴된 BW는 0 BW인데 블록만 10개가 억지로 생성됩니다.
신규 유저 100명이 누르면 채굴량 0 BW에 블록만 +100개가 늘어납니다.
이 때문에 대시보드의 **[실시간 BW 발행량 수치]**와 [실제 블록 개수] 간의 1:1 일치 비율이 완전히 깨지고, 채굴 수량보다 블록 개수가 멋대로 앞서 나가는 기현상이 벌어졌던 것입니다.
4. 올바른 [마이닝 시작] 함수의 본래 역할
[마이닝 시작(startMining)] 기능은 **"이 유저가 채굴을 시작했음(isMining = true)을 기록하고 시계를 돌리는 역할"**만 해야 합니다.
채굴 시작 버튼을 눌렀다고 해서 블록을 공짜로 발급해 주면 안 되며, 블록은 오직 유저들이 채굴을 계속 진행하여 [전체 실시간 발행량 BW]가 다음 정수(1 BW)를 넘어설 때만 단일 통제 엔진에 의해 정식으로 생성되어야 합니다.
