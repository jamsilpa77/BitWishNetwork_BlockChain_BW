2. **유저 마이닝 페이지 요청 시 중복 덤프 (`MiningController.ts`)**:
   * 유저가 웹페이지를 열어 `/user-status`나 `/sync`를 호출할 때마다, 서버가 전체 global cap 오차를 유저 개별 블록 생성으로 잘못 계산하여 단 몇 초 만에 수십~수백 개의 블록을 과다 생성했습니다.
3. **일시금 보너스 수령 시 Threshold 미갱신 오차 (`partner.ts`)**:
   * 출석/추천 일시금 보너스가 수령될 때 `accumulatedReward` 수치는 늘어나지만, 마지막 블록 생성 지점인 `lastBlockRewardThreshold`가 즉시 갱신되지 않아 백그라운드 Worker가 이를 미생성 갭으로 착각하고 연쇄 생성했습니다.
4. **글로벌 Cap Guard로 인한 마이닝 락 (채굴 멈춤 현상)**:
   * 메인넷 백그라운드 Worker(`server/index.ts`)는 전체 DB 물리 블록 수가 전체 발행 BW 수량을 초과하면 **"전체 마이닝 블록 생성 락(Lock)"**을 걸었습니다.

## 🛠️ [2공정] 백엔드 블록 생성 코드를 유저 개별 1BW 1대1 실시간 생성 구조로 일원화

2공정의 핵심 목표는 **"어떠한 외부 요인이나 전역 락에 방해받지 않고, 21개 지갑 개개인이 채굴/보상을 통해 1 BW 정수를 돌파할 때마다 즉시 본인 지갑 명의로 1개 블록을 만들어주는 단일 통제 엔진 구축"**입니다.

### 📍 Step 2-1. 가상/중복 블록 생성 코드 전면 삭제 (Code Cleanup)
1. **가상 블록 생성 제거 (`server/controllers/UserController.ts`)**:
   * 추천인 등록 및 가입 보너스 지급 시 BW 코인 asset 증가 없이 `Height 100000+`, `200000+` 등의 임의 블록을 `blocks` DB에 무단 삽입하던 `saveRegistrationReward` 내의 `blocks.insertOne` 로직을 **전면 삭제**합니다.
2. **유저 API 내 백그라운드 다중 덤프 제거 (`server/controllers/MiningController.ts`)**:
   * 유저가 마이닝 페이지를 열거나 갱신할 때(`/user-status`, `/sync`) 백그라운드에서 불필요하게 실행되어 수십 개씩 블록을 중복 덤프시키던 자동 동기화 루프를 제거합니다.
3. **전역 Cap Guard 락 전면 파기 (`server/index.ts`)**:
   * 메인넷 전체 물리 블록 수가 전체 발행 BW를 넘어서면 모든 유저의 채굴 블록 생성을 차단해 버리던 `Global Cap Guard`전역 락(`netDbBlocks >= grandTotalBW`)을 **전면 파기**하고, 오직 **개별 지갑 단위 1:1 검증 방식**으로 전환합니다.

### 📍 Step 2-2. 중앙 통제 단일 검증 엔진 구축 (`BlockMiningService.ts`)
1. **`syncUserBlocks(walletAddress)` 단일 원자적 함수 신설**:
   * 백엔드의 모든 블록 생성을 오직 이 함수 하나로 집결시킵니다.
   * **검증 연산식**:
     $$\text{목표 블록 수}_i = \lfloor \text{유저별 총 보유 BW (마이닝 + 보너스 + 정산액)}_i \rfloor$$
     $$\text{현재 DB 블록 수}_i = \text{db.blocks.countDocuments}(\{\text{validator}: \text{walletAddress}\})$$
   * **생성 조건**:
     만약 $\text{현재 DB 블록 수}_i < \text{목표 블록 수}_i$ 인 경우, 그 부족분 수량(Diff)만큼 정확히 해당 유저 명의의 실물 PoW 블록을 즉시 추가 생명 및 검증(`blocks` & `blocktransactions` 1:1 삽입)합니다.
2. **일시금 보너스 동시 원자적 갱신 (`partner.ts`, `UserController.ts`)**:
   * 출석/추천/가맹점 보너스로 +1 BW, +3 BW 등의 일시금이 들어올 경우, `accumulatedReward`증가와 동시에 `lastBlockRewardThreshold`를 동시 갱신하여 갭 오차 없이 실물 블록 1개, 3개가 즉각 정밀 발행되도록 구현합니다.

### 📍 Step 2-3. DB 1대1 참값 칼동기화 스크립트 실행 (`sync-blocks-1to1.ts`)
1. **보유 자산 100% 온전 보존**:
   * 21개 지갑의 유저가 보유한 실질 BW 자산(마이닝, 확정 정산액, 보너스)은 단 0.00000001 BW도 차감 없이 **`100% 완전 보존`**합니다.
2. **블록 수량 1:1 완벽 정산**:
   * 21개 지갑 각각에 대해 $\text{블록 수}_i = \lfloor \text{총 보유 BW}_i \rfloor$ 가 되도록, 이전에 덤프 삽입되었던 중복/허수 블록을 안전 소거하고 부족한 지갑에는 실물 블록을 정밀 보충합니다.
   * **결과**: 메인넷 전체 물리 블록 수량이 참값 총 발행량 BW의 정수 수치와 **`1:1로 100% 완전 일치`**하게 됩니다.

## Ⅲ. 이전 AI가 저지른 기술적 결함 및 구조적 오염 전수 분석

이전 AI 개발자가 코드베이스에 남겨놓은 근본적 결함 6가지를 정밀 파악하였습니다.

```
[이전 AI가 만든 누더기 구조적 버그 6가지]

① Global Cap Guard (전역 락) ───► 블록 > BW 상태일 때 메인넷 전체 블록 생성을 강제 잠금 (원칙 위반)
② threshold 선행 갱신 버그 ─────► Cap Guard 잠금 중에도 threshold를 올려버려, 잠금 해제 후 해당 구간 블록 영구 누락
③ 100000/200000번대 가상 블록 ──► BW 자산 증명 없는 허수 블록을 DB에 생성하여 블록 수만 12개 혼자 앞서감
④ MonthlySettlement 이중 산입 ──► MiningState 안에 이미 포함된 3,293 BW를 밖에서 한번 더 더해 목표치를 10,375로 뻥튀기
⑤ 무인 워커 save() 실패 무한루프 ─► Mongoose .save() 실패로 dbAmount가 675.9990 BW에 갇혀 15초마다 릴레이 폭증
⑥ 파편화된 블록 생성 경로 ────► MiningController, UserController, partner, index 등에서 각자 블록을 생성해 충돌
```

### 1. `Global Cap Guard` (전역 락) 개념 자체가 블록체인 원칙 위반
- 이전 AI는 허수 블록 과생성 버그를 근본적으로 고치지 못하자, `isGlobalCapReached = currentBlockCount >= targetBlockCount` 라는 전역 잠금장치를 강제로 씌웠습니다.
- 이로 인해 특정 유저가 1 BW를 정상 채굴했음에도 네트워크 전체 수치가 안 맞는다는 이유로 블록 생성을 거부당하고 멈추는 비정상 현상이 발생했습니다.

### 2. Cap Guard 잠금 중 `threshold` 선행 갱신 버그 (블록 영구 누락)
- [`server/index.ts`](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/server/index.ts#L129) L129: Cap Guard로 블록 생성은 막아놓았으면서, 유저의 `lastBlockRewardThreshold` 기준점은 실시간 채굴량에 따라 계속 올려버렸습니다.
- **결과**: 나중에 Cap Guard 잠금이 풀려도, 유저의 기준점(`lastThreshold`)이 이미 높아져 있어 `nextThreshold` 조건을 충족하지 못하고 **해당 1 BW 구간의 블록 생성이 영구적으로 씹히고 누락**되었습니다.

### 3. BW 자산 증명 없는 가상 허수 블록(100000번대) 생성 결함
- [`UserController.ts`](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/server/controllers/UserController.ts) L229/L304: 추천인 관계 형성 시 실제 BW 잔액 증가 없이 `100000번대`, `200000번대` 가상 높이 블록을 DB에 강제 삽입했습니다.
- **결과**: 실제 BW 발행량(7,056 BW)보다 DB 블록 수(7,068개)가 **12개나 먼저 튀어나가는 원인**이 되었습니다.

### 4. `MonthlySettlement` (3,293 BW) 이중 중복 산입 공식 결함
- [`BlockMiningService.ts`](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/server/services/BlockMiningService.ts#L194) L194 & [`index.ts`](file:///c:/BitWishNetwork_BlockChainMainnet/BitWishNetwork_MiningSystem/server/index.ts#L74) L74:

### 5. `autoRestoreMiningStates()` 30초 루프의 `state.save()` 반영 누락 및 15초 폭증
- 30초 무인 워커 실행 시 Mongoose 모델의 `.save()`가 MongoDB 원장에 `lastBlockRewardThreshold`를 제때 갱신하지 못했습니다.

4. **50자리 정밀도 참값 총 자산 및 정수 계산** [L78~80, L98~99]

비트위시 네트워크(BitWish Network)의 블록체인 무결성(1 BW = 1 Physical Block)을 영구적으로 완수하고, 보상/보너스 수량의 표출 누락 및 물리적 블록 부족 현상을 근본적으로 해결하기 위한 **[2단계 완벽 수복 및 영구 통합 블록 민팅 시스템 구축 계획서]**를 보고드립니다.

---

# 1. 수복 작업의 3대 핵심 철학 및 원칙

1. **자산 표출 100% 완벽 일치**: DB에 저장되어 있는 4대 자산(순수 채굴, 1BW 가입 보상, 2% 마이닝 보너스, 확정 정산액)이 단 0.00000001 BW도 누락되지 않고 홈페이지 대시보드와 유저 대시보드에 영구 표출되어야 합니다.
2. **블록체인 원칙 준수 (1 BW = 1 Block)**: 체인 무결성을 위해 총 자산의 정수량(`7,156 BW`)과 물리적 블록 높이(`7,156개`)가 단 1개의 오차도 없이 1:1로 완전 일치해야 합니다.
3. **블록 체이닝 무결성 보장**: 부족한 62개 블록 수복 시 임의 생성이 아닌, 기존 블록의 이전 해시(`previousHash`), 난이도(`difficulty`), 트랜잭션 수량(`blocktx`), 타임스탬프를 100% 검증하는 **정식 보상 트랜잭션 블록체인 수복 알고리즘**을 적용합니다.

---

# 2. [1단계] 과거 데이터 100% 완벽 수복 절차 (즉시 적용안)

### 과제 (1) 홈페이지 표출 API (`stats.ts`) 영구 수정
* **문제점**: 기존 API는 `순수채굴 + 확정정산 + 1BW가입보상`만 더하고 **`2% 추천 보너스(referralBonusStorage)`를 누락**했습니다.
* **수복 방안**: `stats.ts` 통계 API 쿼리를 아래와 같이 수정하여 4대 자산을 100% 완벽 합산합니다.
  $$\text{실시간 총 발행량} = \text{minedBW} + \text{MonthlySettlement} + \text{referralRewardStorage} + \text{referralBonusStorage}$$
* **결과**: 홈페이지 표출량이 기존 `7,093.82 BW`에서 터미널 검증 수치인 **`7,156.50 BW`로 즉시 완벽 일치**하게 됩니다.

---

### 과제 (2) 부족한 62개 물리적 블록 완벽 주조 (Block Minting Repair)
* **문제점**: DB 내 생성된 물리적 블록 수(`7,094개`)가 정수 발행량(`7,156개`) 대비 **62개 부족**합니다.
* **수복 방안**: `mint-missing-reward-blocks.ts` 전용 수복 스크립트를 작성하여 62개의 보상 블록을 연속 주조합니다.
  - **블록 높이**: `7,095번`부터 `7,156번`까지 순차 생성
  - **트랜잭션 내용**: 미채굴자 13명의 1BW 보상(`18개`) + 채굴자 8명의 보상/보너스 누락분(`44개`)에 대한 `SYSTEM_REWARD_MINT` 트랜잭션 생성 및 `blocktx` DB 업로드
  - **해시 체이닝**: 7,094번 블록의 `hash`를 7,095번의 `previousHash`로 참조하고, 매 블록마다 SHA-256 해시를 정상 연산하여 저장
* **결과**: 체인 상의 **최종 블록 높이가 `7,156 블록`으로 자산 정수와 1:1 완벽 일치**를 달성합니다.

---

# 3. [2단계] 향후 신규 발생 보상/보너스의 영구 자동 블록 민팅 엔진 구축 (향후 시스템)

앞으로 추천인 가입 및 2% 추천 보너스가 발생할 때 더 이상 블록 누락이나 발행량 오차가 발생하지 않도록 백엔드 모듈을 3대 구조로 영구 개편합니다.

```
                  [신규 추천 가입 / 2% 마이닝 보너스 발생]
                                    │
                                    ▼
                     [보관함 누적 (referralStorage)]
                                    │
                                    ▼
          [Real-Time Reward Monitor (보상 1BW 감지 엔진)]
                                    │
                         ┌──────────┴──────────┐
                         │ 1 BW 돌파/생성 감지  │
                         └──────────┬──────────┘
                                    │
                                    ▼
           [System Reward Block Minting Engine (블록 주조)]
                                    │
                ┌───────────────────┴───────────────────┐
                ▼                                       ▼
    [물리적 Block (height +1) 생성]            [blocktx 트랜잭션 기록 완료]
```

### (1) 추천인 가입 보상 (1BW) 영구 자동 처리
* **작동 방식**: 신규 회원이 추천인 코드로 가입하는 즉시, 추천인과 피추천인의 `referralRewardStorage`에 1BW가 쌓이는 것과 동시에 **`RewardBlockService`가 호출되어 즉시 1개의 물리적 보상 블록(`System Reward Block`)을 민팅**합니다.
* **효과**: 가입 보상이 발생하는 순간 블록체인에 트랜잭션이 영구 기록되며, 채굴 버튼을 누르지 않아도 물리적 블록이 1:1로 100% 즉시 생성됩니다.

### (2) 2% 실시간 추천 보너스의 '1 BW 돌파 시 자동 블록 민팅' 엔진 구축
* **작동 방식**: 마이닝 백엔드 루프에 `CheckAndMintReferralBonusBlocks()` 모니터링 파이프라인을 추가합니다.
  - 유저의 `referralBonusStorage` 누적 수치가 **정수 1 BW에 도달할 때마다** (예: 1.0 BW, 2.0 BW, 3.0 BW ...)
  - 시스템이 자동으로 **1 BW 물리적 블록 1개를 주조**하고 `referralBonusStorage`에서 1 BW를 차감하여 정산 계정으로 이동시킵니다.
* **효과**: 추천 보너스로 1 BW가 쌓이는 족족 블록체인 상에 실시간 물리적 블록이 구워져 자산과 블록의 격차가 영구적으로 0이 됩니다.

### (3) 통합 메인 블록체인 시퀀서 (Unified Block Sequencer)
* **작동 방식**: 
  1. `순수 마이닝 블록`
  2. `추천 가입 보상 블록`
  3. `2% 마이닝 보너스 블록`
  위 3가지 형태의 블록이 하나의 중앙 **`Unified Block Sequencer`**를 통과하게 만듭니다.
* **효과**: 블록 높이(`block height`)가 겹치거나 뒤틀리지 않고 단일 체인 위에서 순차적으로 안전하게 커밋(Commit)됩니다.

이후 수복 작업을 진행할 때는 아래 4단계 표준 공정에 따라 완벽하게 검증하며 진행합니다.

### 🔍 출석 및 가맹점 보너스의 백엔드 작동 원리 (`MiningController.ts`)

1. **연산 공식 (`MiningController.ts` L83~94)**:
   $$\text{currentTotalRate} = \text{baseRate} \times (1 + \text{attendanceRate}) \times (1 + \text{referralRate}) \times (1 + \text{partnerRate}) \times (1 + \text{extensionRate})$$
   - **출석 보너스 (`attendanceRate`)**: 출석 체크 완료 시 `isAttendanceActive = true`가 되며 기본 채굴 속도(`0.25 BW/h`)에 **+5% 가산 승수**를 부여합니다.
   - **가맹점 보너스 (`partnerRate`)**: 본사 승인 시 `partnerStatus = 'REGISTERED'`가 되며 기본 채굴 속도에 **+125% 가산 승수 (`1.25`)**를 부여합니다.

2. **자산 적립 및 블록 민팅 파이프라인**:
   - 출석 체크(+5%)와 가맹점(+125%)으로 높아진 채굴 속도로 계산된 채굴량은 별도의 보관함이 아닌 유저의 초당 채굴 수치인 **`accumulatedReward` (순수 채굴 누적액)**에 실시간으로 더해집니다.
   - `MiningController.ts` L312~333 코드에 따라 `accumulatedReward`가 정수 1 BW를 넘을 때마다 `BlockMiningService.onMiningBlock()`이 호출되어 **물리적 블록이 정상적으로 주조(Minting)**되어 왔습니다.

3. **21명 지갑 데이터 전수 조사 결과**:
   - **가맹점 회원**: 21명 중 가맹점 승인 회원(`REGISTERED`)은 **`0명`** (전원 미등록 상태).
   - **출석 체크 회원**: 8명 채굴 유저의 출석 체크로 인한 5% 증분 채굴액은 이미 `accumulatedReward` (총 **`3,768.76 BW`**)와 생성된 **`4,692개` 블록** 속에 **100% 반영**되어 있었습니다.

# 2. 종합 검증 결과 및 수복 대상 재확인

* **누락되었던 진짜 원인 대상 (2가지)**:
  1. **추천인 가입 보상 (1BW 계통, 32 BW)**: DB 보관함에는 존재하나 물리적 블록 미생성 (`-32개` 부족분 발생).
  2. **추천 2% 마이닝 보너스 (62.61 BW)**: DB 보관함에는 존재하나 **홈페이지 대시보드 API 쿼리 누락** 및 물리적 블록 미생성.

* **이미 정상 작동 중인 대상 (2가지)**:
  1. **출석 보너스 (5%)**: 채굴 속도 가산 방식으로 `accumulatedReward` 및 물리적 블록에 **이미 100% 정상 합산 및 블록 주조 완료**.
  2. **가맹점 보너스 (125%)**: 채굴 속도 가산 방식으로 `accumulatedReward` 및 물리적 블록에 **이미 100% 정상 연동 구조 완성**.

### 📌 수복 작업 3대 실행 계획

#### 1. 홈페이지 표출 API (`stats.ts`) 영구 수복
* 기존 누락되었던 `referralBonusStorage` (2% 추천 보너스, 62.61 BW)를 통계 쿼리에 합산 처리.
* **결과**: 홈페이지 실시간 현재 BW 발행량이 `7,093.82 BW`에서 터미널 실제 총합인 **`7,156.50 BW`로 즉시 정밀 일치**.

#### 2. 과거 누락 물리적 블록 62개 수복 주조 (Block Minting)
* 출석/가맹점 보너스는 이미 블록이 주조되어 있었으므로, **추천 가입보상 및 2% 추천보너스로 인해 생성되지 못했던 62개 블록(Height 7,095 ~ 7,156)**을 SHA-256 해시 체이닝 검증 알고리즘에 따라 물리적 블록으로 완전 주조.
* **결과**: 블록체인 물리적 블록 높이가 **`7,156 블록`으로 정수 자산과 1:1 완벽 일치**.

#### 3. 향후 4대 보상 계통 통합 자동 블록 민팅 파이프라인 구축
* **순수 채굴 (출석 + 가맹점 승수 포함)**: 기존과 동일하게 1 BW 경계 돌파 시 실시간 블록 생성.
* **추천 가입 보상 (1BW)**: 회원 가입 즉시 `System Reward Block` 1개 자동 민팅.
* **추천 2% 보너스**: 보관함 누적액이 정수 1 BW를 돌파할 때마다 실시간으로 보너스 블록 1개 자동 민팅.
