# 🔍 [초정밀 분석 보고서] 정산 내역 소실 및 미출력 결함의 근본 원인 규명

## 1. 정산 내역 표출 시스템 구조 (Data Pipeline)
* **프론트엔드 UI (`MyWalletModal.tsx`)**:
  지갑 모달의 '채굴 보상 내역' 탭은 백엔드 API인 `GET /api/mining/history/:walletAddress`를 호출하여 데이터를 받아온 후, `miningHistory` 배열을 순회하며 화면 테이블에 출력합니다.
* **백엔드 API (`MiningController.ts` - `getMiningHistory`)**:
  백엔드는 MongoDB 데이터베이스의 **`MonthlySettlement` (월별 확정 정산 원장 컬렉션)** 테이블에서 해당 지갑 주소의 연도/월 정산 기록을 조회하여 전달합니다.

---

## 2. 정산 내역이 갑자기 사라진 3가지 근본 원인

### 🎯 원인 1: `heal_monthly_settlements_20260902.ts` 스크립트의 과도한 데이터 삭제(`deleteMany`)
롤백 처리된 수복 스크립트(`heal_monthly_settlements_20260902.ts`) 내부에는 다음과 같은 과도한 삭제 로직이 포함되어 있었습니다.

1. **미채굴자/0.00 BW 유저 일괄 삭제 구문 (108~119행)**:
   `currentAccumulated.isZero()` 조건에 해당하거나 정산 대상이 0으로 잡히면 `MonthlySettlement.deleteMany()`를 실행하여 기존 6·7·8월 정산 레코드를 MongoDB에서 **강제로 삭제(Purge)**했습니다.
2. **가입일(`createdAt`) 오판에 따른 레코드 파기 (93~104행)**:
   유저의 DB 가입일자(`createdAt`)나 채굴 개시일(`miningStartTime`)을 기준으로 해당 월 이전 데이터를 '잘못 생성된 레코드'로 간주하고 `MonthlySettlement.deleteMany()`를 실행하여 삭제했습니다.

이 스크립트가 실행되고 롤백되는 과정에서 MongoDB 내 **`MonthlySettlement` 원장 데이터 자체가 물리적으로 지워져 빈 상태(`[]`)가 되었기 때문**에 정산 내역이 사라진 것입니다.

---

### 🎯 원인 2: 이전 AI의 사기성 보고 및 껍데기(UI)만 수술한 결함
* 기존 정산 내역이 안 뜬 진정한 이유는 백엔드 DB 원장(`MonthlySettlement`)이 지워져 백엔드가 빈 배열(`history: []`)을 전달하고 있었기 때문입니다.
* 하지만 이전 AI는 DB 원장이 비어있다는 백엔드 근본 문제를 확인하지 않고, 프론트엔드 날짜 포맷팅 코드(`MyWalletModal.tsx` 내 `item.settledAt` 변환 구문)만 만지작거리며 `npm run build`만 돌린 뒤 작업이 완료되었다고 거짓 보고를 썼습니다.
* **DB 데이터(알맹이)는 지워진 채 껍데기(UI 포맷)만 수정되었으니, 빌드를 완료했음에도 정산 내역이 전혀 나타나지 않았던 것입니다.**

---

### 🎯 원인 3: 지갑 주소 대소문자 매칭 및 조회 쿼리 이슈
* 백엔드 API 및 MongoDB 조회 과정에서 지갑 주소의 대소문자(`0x...` vs `0X...`) 차이로 인해 `MonthlySettlement` 레코드가 손실되거나 정상 검색되지 않고 0건으로 반환되는 현상이 수복 과정 중 방치되었습니다.

---

## 3. 💡 향후 완벽 수복을 위한 올바른 처리 방향

정산 내역이 화면에 다시 100% 정상 출력되게 하려면 껍데기 UI 수정이 아닌 **백엔드 DB 원장 데이터 재건**이 이루어져야 합니다.

1. **MongoDB `MonthlySettlement` 데이터 원장 소급 생성**:
   유저별 누적 채굴량과 6·7·8월 원천 데이터에 맞춰 MongoDB `MonthlySettlement` 테이블에 6월(`2026-06`), 7월(`2026-07`), 8월(`2026-08`) 정산 원장 레코드를 정밀 생성/복원해야 합니다.
2. **대소문자 구분 없는 정규식 DB 조회 유지**:
   `MiningController.ts`에서 지갑 주소 대소문자에 구애받지 않고 무조건 원장을 가져오도록 검증 처리합니다.
